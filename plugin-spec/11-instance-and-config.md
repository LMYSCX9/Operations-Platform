# 11 实例、配置与自报边界

> 契约版本：**1.2** ｜ 关联：ADR-0023、DOC-17（纯文本引用）、[plugin-spec/01](01-manifest.md)、[plugin-spec/03](03-remote-protocol.md)、[plugin-spec/08](08-directory-layout.md)
> 本文件说明插件作者必须遵守的实例与配置规则。注册与状态事实由底座掌握，插件不参与「注册」。

## 1. 一个包，多台主机，多个实例

- 同一个插件包可以被安装到多台主机，产生多个**实例**；每个实例有独立的配置文件、数据目录、端口与运行状态。
- 插件**不得**假设自己是全局唯一实例：不得在共享路径写单例文件、不得占用固定全局端口、不得依赖「只有一个我」。
- 插件**不得**在实例之间共享状态文件、缓存或锁；所有持久数据只能写入 `--ops-data-dir`。
- 实例标识通过 `--ops-instance-id` 传入；插件可写入日志以便排障，但不得据此改写配置或端口。

## 2. 能力与版本：只声明，不自报注册

- 能力清单只来自包内 `plugin.yaml`，由底座校验并注册；插件**没有**「注册能力」的接口。
- `GetVersion` 必须如实返回插件版本与实际契约版本；底座用它比对清单，不一致时判定漂移并隔离。
- 不得通过日志、stdout、健康接口或任何自定义 RPC 发布「新增能力」；底座不会采纳。
- 不得在运行时改变能力集合；新增/删除能力必须发布新版本并重新安装。

## 3. 配置声明

清单 `config` 声明本插件的可配置项（见 [01-manifest.md](01-manifest.md) §5）：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `key` | 是 | 配置键，`^[a-z][a-z0-9_]*$`，在类型内唯一 |
| `type` | 是 | `string` / `number` / `integer` / `boolean` / `enum` |
| `required` | 否 | 是否必填，缺省 `false` |
| `secret` | 否 | 是否敏感，缺省 `false`；敏感值不得出现在日志/错误详情 |
| `default` | 否 | 默认值（`secret` 不得有默认值） |
| `enum` | 否 | `type: enum` 时的候选值 |
| `description` | 否 | 面向用户的说明 |

规则：

- `secret: true` 的值由底座加密存储，并在生成配置文件时以明文写入权限受限的文件（`0600`）；插件读取后不得再落盘。
- 配置值按**实例**填写；插件不得内置「某台主机专用」的硬编码值。
- 配置缺失且必填 → 插件必须启动失败或 `Ready=false`，并给出可诊断原因（`config_invalid`）。
- 未知配置键必须忽略，不得因此启动失败。
- 配置项类型/枚举在版本升级中发生变化时，由底座阻止升级；插件不得自行转换。

## 4. 配置来源与加载

- 唯一来源是 `--ops-config` 指向的配置文件；不得从环境变量读取配置。
- 本机与远端使用同一配置格式（YAML）；远端额外包含 `deployment`、`listen`、`tls` 段（见 [03-remote-protocol.md](03-remote-protocol.md) §3.2）。
- **实现状态**：本机 daemon 托管尚未实现（OQ-044），本机实例请使用命令式形态；远端 daemon 只能经底座下发运行，
  配置与证书由底座生成，不得手工部署或注册 unit。
- 插件只读该文件，不得回写；不得缓存后覆盖用户修改。
- 文件不可读 / 解析失败 / 必填缺失 → 启动失败，不降级为默认值继续运行（除非该项声明了 `default`）。
- 敏感值不得写入插件自己的日志、审计或数据目录。

## 5. 数据目录

- 每个实例独立 `--ops-data-dir`；插件只能读写该目录与自身包目录。
- 不得读写其他实例、其他插件或底座数据目录。
- 升级时底座保留数据目录；插件必须兼容旧版本数据，或在启动时显式报错（不得静默清空）。

## 6. 状态自报边界

| 允许 | 禁止 |
| --- | --- |
| `GetVersion` 如实返回版本 | 用自报版本覆盖包记录 |
| `Ready` / `Health` 如实返回自身状态 | 把自报健康当作唯一可调用依据（底座仍会探测） |
| 日志中记录实例标识与配置摘要 | 在日志中记录敏感配置值 |
| 启动时校验配置并失败 | 启动后自行改写配置或端口 |

底座以「安装事实 + 探测」为准；自报仅用于比对与漂移告警。插件不得因此拒绝服务或要求底座「信任我」。

## 7. 自测清单

- [ ] 多实例安装时不会互相覆盖数据或端口。
- [ ] 所有持久数据只写入 `--ops-data-dir`。
- [ ] `config` 声明完整；必填缺失时启动失败且原因可诊断。
- [ ] `secret: true` 的值不出现在日志、错误详情、stdout。
- [ ] 只读 `--ops-config`，不回写、不从环境变量取配置。
- [ ] 未识别配置键与未知 `--ops-*` 参数被忽略。
- [ ] `GetVersion` 返回真实版本与契约版本。
- [ ] 不存在「注册能力/上报能力」的自定义接口。
- [ ] 升级后能读取旧数据目录或显式报错，不静默清空。
