# PS-10 插件开发常见问题（已定结论）

> 依据：底座 ADR-0003~0006、ADR-0018~0023（均为 `accepted`）｜ 契约版本：`1.2`
>
> 本文件回答「规范没写、插件作者只能来问」的问题。每条都标注性质：
>
> - **契约强制**：底座会校验或拒绝，违反即不合规。
> - **实现建议**：底座不校验，但按此实现可避免已知问题。
> - **待定**：尚无结论，已登记 OQ；不要自行决定，按 §16 流程提问。

## 1. 进程由谁拉起与托管

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| 本机常驻插件要不要自己守护进程？ | 契约形状是「不要，底座以子进程方式拉起并托管」；但底座**本机 daemon 托管尚未实现**（OQ-044），**当前本机实例请使用命令式形态** | 实现状态 |
| 远端常驻插件谁拉起？ | 目标机 **systemd**；unit 由底座生成并下发，插件**不得**自带 unit 或自建服务 | 契约强制 |
| 能注册额外 systemd / Windows 服务吗？ | 不能。不得 daemonize、不得写 pid 文件、不得在底座下发的 unit 之外再注册服务 | 契约强制 |
| 插件能接管重启策略吗？ | 不能。本机托管实现后由底座退避与上限决定（数值待 OQ-044），当前本机请用命令式；远端由 systemd `Restart=on-failure` 决定 | 契约强制 |
| 远端主机上的 daemon 怎么办？ | **只能经底座下发运行**：底座通过 SSH 上传安装包、生成配置/证书/systemd unit 并 `systemctl daemon-reload + enable --now`；**不支持也不得手工部署二进制或注册 unit**。前提是清单声明 `runtime.listen.port` | 契约强制 |
| 能假设自己只有一个实例吗？ | 不能。同一插件可在多台主机上各有一个实例；本机重新拉起时 `instance-id` 也会变 | 契约强制 |
| 同一插件能同时本机托管又被远端托管吗？ | 不能。同一主机 + 同一插件只允许一种托管方式 | 契约强制 |

## 2. socket 与配置路径怎么传入

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| socket 路径谁决定？ | 本机托管实现后由底座决定，经 `--ops-socket` 传入；插件只能监听该路径。当前本机 daemon 托管未实现（OQ-044），本机请用命令式 | 契约强制 |
| 配置从哪读？ | `--ops-config` 指向的只读文件；也可用 `--ops-data-dir` 下的自有状态 | 契约强制 |
| 远端监听地址与端口从哪来？ | 只从 `--ops-config` 配置文件的 `listen.address` / `listen.port` 读取；远端**不注入** `--ops-socket` | 契约强制 |
| 远端能用证书路径以外的写死值吗？ | 不能。证书、私钥、CA 路径以配置文件 `tls.*` 为准，插件不得替换 | 契约强制 |
| 能用环境变量取路径吗？ | 不能依赖环境变量获取注入信息 | 契约强制 |
| 能假设当前工作目录吗？ | 不能；所有资源路径必须显式解析 | 契约强制 |
| 能自己选 socket 路径或监听 TCP 吗？ | 本机不能监听 TCP；远端只能监听配置文件中声明的地址 | 契约强制 |
| 参数名改了怎么办？ | 参数名属契约：新增 = MINOR，改名/删除/改语义 = MAJOR | 契约强制 |
| 不认识新参数怎么办？ | 必须忽略未知 `--ops-*` 参数与未知配置字段，不得因此退出 | 契约强制 |

完整参数表见 [03-remote-protocol.md](03-remote-protocol.md) §2。

## 3. 凭据与证书怎么安全传递

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| 凭据能放环境变量或命令行吗？ | 不能（既有禁令） | 契约强制 |
| 本机启动时怎么拿到凭据？ | 读 `--ops-credential-file` 指向的一次性文件（`0600`），读后**立即删除** | 契约强制 |
| 长期运行的凭据会过期吗？ | 会。每次 `Invoke` 的 `context.credential` 携带新凭据，以最近一次为准 | 契约强制 |
| 远端也需要一次性凭据文件吗？ | 不需要，远端**不注入**该文件；身份由双向 TLS 证书承担，`context.credential` 不是身份依据 | 契约强制 |
| 远端证书与私钥放在哪？ | 路径来自 `--ops-config`；私钥 `0600`、证书与 CA 证书 `0644`、状态目录 `0700`，不得搬走或放宽权限 | 契约强制 |
| 远端要校验调用方吗？ | 要。必须用 CA 证书校验客户端证书，且客户端标识必须等于配置文件中的期望底座标识 | 契约强制 |
| 能自己生成/替换证书吗？ | 不能。证书由底座内置 CA 在下发安装时签发 | 契约强制 |
| 能把凭据或私钥写到数据目录缓存吗？ | 不能 | 契约强制 |
| 凭据/私钥能出现在日志/错误里吗？ | 不能 | 契约强制 |
| 插件能自己签发凭据吗？ | 不能，签发与授权都在底座（ADR-0006） | 契约强制 |
| 有效期多长？ | 待定（OQ-044 本机凭据 / OQ-047 证书） | 待定 |

## 4. 退出码与错误类别怎么对应

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| daemon 要用退出码表达结果吗？ | 不要。daemon 无退出码语义，错误只经 `InvokeResponse.error` | 契约强制 |
| 命令式插件退出码有几个？ | 固定 0~8 共 9 个；不得用 9 及以上 | 契约强制 |
| 目标不存在该用什么？ | `not_found`（不是 `capability_unknown`，也不是 `input_invalid`） | 契约强制 |
| 字段齐全但值冲突用什么？ | `validation_failed` | 契约强制 |
| 状态不允许执行用什么？ | `precondition_failed` | 契约强制 |
| 用新类别要注意什么？ | `contract` 下限必须 ≥ `1.1`，否则会被归一为 `internal_error` | 契约强制 |
| 退出码与 `code` 不一致会怎样？ | 底座判协议不一致并记录；以失败处理 | 契约强制 |
| daemon 崩溃了调用方看到什么？ | `internal_error`（有在途调用时），不是业务类别 | 契约强制 |

完整枚举与映射见 [05-errors-and-exit-codes.md](05-errors-and-exit-codes.md) §2、§3。

| 能用其它未批准的依赖吗？ | 不能，新增依赖必须先走 ADR | 契约强制 |

## 6. 能力如何命名与拆分

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| 能力标识格式？ | 强制 `<插件标识>.<能力名>`，两段都匹配 `^[a-z][a-z0-9-]*$` | 契约强制 |
| 能做一个万能 `execute` 吗？ | 不能，一个能力一个明确动作 | 契约强制 |
| 能加 `setup` 能力吗？ | 不能；初始化必须幂等、无交互，用 `--ops-config` 或普通能力表达 | 契约强制 |
| 能加 `version` 能力吗？ | 不能；版本由 `GetVersion`（daemon）或清单 `version.plugin`（command）承担 | 契约强制 |
| 能力能改名吗？ | 不能；改名 = MAJOR，语义变更必须新增能力 | 契约强制 |
| 能力怎么拆？ | 按「调用方要做的决定」拆，而不是按内部函数拆；不同处置方式（改输入 / 换目标 / 等状态）应落在不同能力 | 实现建议 |

## 7. 高危操作如何确认

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| 高危操作确认是建议还是强制？ | 契约强制，插件必须在任何副作用前校验 | 契约强制 |
| `delete` 要什么字段？ | `confirm_partition`，且必须**严格等于**目标分区标识 | 契约强制 |
| `restore` / `gc` 要什么字段？ | `confirm: true` + 目标字段（`target` 或 `partition`） | 契约强制 |
| 谁来校验？ | 插件校验值；底座只做静态一致性校验与调用前审计 | 契约强制 |
| 能靠 UI 二次确认兜底吗？ | 不能；API 直调与定时任务同样必须携带确认字段 | 契约强制 |
| 缺失时用什么类别？ | 字段缺失 → `input_invalid`；值不匹配 → `validation_failed`；`confirm=false` → `precondition_failed` | 契约强制 |
| 清单要标什么？ | 能力名末段为 `delete`/`restore`/`gc` 时必须 `risk_level: destructive` | 契约强制 |

## 8. 日志与观测有什么要求

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| 能往 stdout 打日志吗？ | 命令式插件不能（stdout 只放结果）；daemon 的 stdout 被接入日志，但也不承载结果 | 契约强制 |
| 日志写哪里？ | 命令式：stderr；本机 daemon（托管实现后）：stderr（stdout 亦被捕获），当前本机请用命令式；远端 daemon：stdout/stderr 由 systemd 写入 journald | 契约强制 |
| 远端能自己写日志文件吗？ | 默认不要；日志由 journald 承载。需要文件日志时只能通过 `config` 声明并写入明确路径 | 实现建议 |
| 日志必须包含什么？ | 时间、级别、`invocation_id`（有调用时）、插件标识；禁止敏感值 | 契约强制 |
| 需要暴露指标吗？ | v1 不要求插件自建指标端点；由底座记录调用耗时与结果类别 | 实现建议 |
| 日志保留多久？ | 待定（OQ-016） | 待定 |

| 构建产物入库吗？ | 插件仓库的 `bin/` 不入库；交付包内含可执行文件 | 实现建议 |
| 打包格式？ | 目录或归档；摘要/签名规则待 OQ-015 | 待定 |

## 10. 版本与兼容声明

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| 当前契约版本？ | `1.2`；底座同时支持 `1.0`、`1.1` 与 `1.2` | 契约强制 |
| 怎么声明？ | `version.contract: ">=1.0 <2.0"`（用新错误类别则 `>=1.1`；用远端形态或 `config[]` 建议 `>=1.2`） | 契约强制 |
| 插件自身版本格式？ | `MAJOR.MINOR.PATCH` | 契约强制 |
| 什么算 MAJOR？ | 删除/改名能力或字段、改必填性、改语义、改 proto 字段编号 | 契约强制 |
| 什么算 MINOR？ | 新增可选字段、新增能力、新增错误类别、新增部署形态（如远端 TCP+mTLS） | 契约强制 |
| 判定在什么时候？ | 安装与启用各判一次，结果写入注册表 | 契约强制 |

## 11. 热加载与重启

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| 改了插件目录会自动生效吗？ | 默认不会；热加载是可选开关且默认关闭 | 契约强制 |
| 插件能自己重载配置吗？ | 能，但重载必须不改变已声明能力集合；能力变化需重新安装/启用 | 实现建议 |
| 重启后状态会保留吗？ | 本机托管实现后：底座会重启进程，插件必须自行从 `--ops-data-dir` 恢复状态（当前本机请用命令式）；远端：systemd 重启进程，状态恢复方式相同 | 契约强制 |
| 崩溃后会无限重启吗？ | 不会。本机超过上限转 `unhealthy`（数值待 OQ-044）；远端由 systemd `Restart=on-failure` 与重启上限约束 | 契约强制 |
| 能复用旧的 socket 文件吗？ | 不能；本机每次启动用新的 `instance-id` 与路径。远端不使用 socket | 契约强制 |
| 远端底座重启后插件会被重启吗？ | 不会。底座只做探测，不重发 unit、不重签证书 | 契约强制 |

## 12. 单实例与并发

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| 同一插件会被并发调用吗？ | 不会。底座为每个**实例**维护单一执行队列，跨能力也串行 | 契约强制 |
| `concurrency: parallel` 有什么用？ | 只声明插件自身线程安全；不改变底座调度 | 契约强制 |
| 多个插件实例之间会并发吗？ | 会，受底座全局并发上限约束（数值待 OQ-017） | 契约强制 |
| 能依赖调用顺序吗？ | 不能把「上一次调用的内存状态」当业务前提 | 契约强制 |
| 插件自己起多个进程/协程可以吗？ | 可以，但必须自行保证数据目录写入安全并遵守关闭时序 | 实现建议 |
| 多个实例共享数据目录吗？ | 不能。每个实例有独立的 `--ops-data-dir`，不得跨实例共享 | 契约强制 |

## 13. 超时与结果体积边界

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| 超时谁定？ | 底座按能力声明与配置决定，通过 `context.deadline_ms` 下发 | 契约强制 |
| 超时了怎么办？ | 必须尽快返回 `timeout`；不可中断的阻塞属违规 | 契约强制 |
| 结果太大怎么办？ | 返回 `result_too_large`，**禁止截断后返回成功** | 契约强制 |
| 具体上限多少？ | 待定（OQ-017）；先按 `runtime.max_result_bytes` 声明 | 待定 |
| 支持流式吗？ | v1 不支持；用「返回句柄 + 查询能力」替代 | 契约强制 |

## 14. 配置文件格式

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| 配置文件格式？ | YAML（与底座配置文件同格式）；路径经 `--ops-config` 传入 | 契约强制 |
| 配置由谁校验？ | 插件自行校验，失败必须让 `Ready` 返回 false 并给出原因 | 契约强制 |
| 能热改配置吗？ | 底座重启插件后才保证生效；插件自行热重载不作承诺 | 实现建议 |
| 能自己找配置吗？ | 不能，只能读 `--ops-config` | 契约强制 |
| 配置里能放凭据吗？ | 不能。用户可配置的敏感项由底座加密存储并写入 `config` 值；证书/私钥不是配置项，不得允许覆盖 | 契约强制 |
| 配置项怎么声明？ | 清单 `config[]` 声明 `key`/`type`/`required`/`secret`/`default`/`enum`/`description`，值由底座按实例填写 | 契约强制 |
| 配置能有一个全局默认值再按主机覆盖吗？ | 能。`default` 是类型级默认，实例值优先；`secret: true` 禁止默认值 | 契约强制 |
| 升级或重装后配置会丢吗？ | 默认保留；类型/枚举变更需迁移（策略待 OQ-051） | 契约强制 |

## 15. 远端部署、证书与端口

| 问题 | 结论 | 性质 |
| --- | --- | --- |
| 怎么表示支持远端部署？ | 清单声明 `runtime.listen.port`；不声明则底座不得把它下发为远端实例 | 契约强制 |
| 实际端口是谁定的？ | 默认取清单值；下发到具体主机时可由实例配置覆盖。以 `--ops-config` 中的值为准 | 契约强制 |
| 端口在证书里吗？ | 不在。证书绑定插件标识、主机标识与用途；改端口**不**触发重签 | 契约强制 |
| 端口一定可达吗？ | 不一定。防火墙与网络策略由用户负责；底座只如实记录不可达 | 契约强制 |
| 端口冲突怎么办？ | 底座在下发校验阶段拒绝；插件不得自行换端口 | 契约强制 |
| 服务怎么启动？ | `systemctl start <unit>`；unit 由底座下发，插件不得自带 | 契约强制 |
| 服务启动就算可调用吗？ | 不算。须再通过 TCP 可达 + TLS 双向校验 + `Ready` + `GetVersion`，才记为「可调用」 | 契约强制 |
| 健康与就绪有什么区别？ | `Ready` 决定能否接调用；`Health` 决定是否需要重启，必须无副作用 | 契约强制 |
| 远端也要实现 `Ready`/`Health` 吗？ | 要，且语义与本机一致 | 契约强制 |
| 证书过期/被吊销会怎样？ | 握手失败，实例不可调用；插件不得回退明文，也不得自行重签 | 契约强制 |
| 证书有效期、轮换周期？ | 待定（OQ-047） | 待定 |
| systemd unit 细节、启动/停止/探测超时、端口范围？ | 待定（OQ-048） | 待定 |

完整远端条款见 [03-remote-protocol.md](03-remote-protocol.md) §3，目录与权限见 [08-directory-layout.md](08-directory-layout.md)。

## 16. 遇到规范没写的问题怎么办

**契约强制**：停下来提问，不得自行决定、不得「按惯例」先做。

1. 先查本文件与 `plugin-spec/` 其余章节；仍未覆盖则停止实现。
2. 向底座维护者提问，说明场景、可选方案与影响面。
3. 结论必须**写回规范正文**（`docs/` 或 `plugin-spec/`），并同步 `.ai/` 索引与开放问题；只存在对话里的答案视为无效。
4. 不允许以「本插件特例」的方式绕过通用约束；确需例外时走 ADR。

详细回流规则见 [AGENTS.md](AGENTS.md) §3。
