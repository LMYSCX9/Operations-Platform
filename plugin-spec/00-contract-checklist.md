# PS-00 契约自查清单

> 提交前逐项勾选。任意一项为「否」都不得认为插件开发完成。
> 清单未覆盖的问题先查 [10-faq.md](10-faq.md)；仍无结论则停下提问并按 [AGENTS.md](AGENTS.md) §5 回流，不得私定。

## A. 元数据（对应 [01](01-manifest.md)）

- [ ] 清单文件名为 `plugin.yaml`，位于包根目录，UTF-8，且通过底座内置 JSON Schema 校验。
- [ ] 清单可被解析，且**必需字段齐全**（身份、版本、形态、入口、能力、运行假设）。
- [ ] 只声明了**一种**形态，且实现与声明一致。
- [ ] 插件标识符合 `^[a-z][a-z0-9-]*$` 且全局唯一；能力标识为 `<插件标识>.<能力名>`。
- [ ] 清单中**没有**任何密钥、口令、令牌，也没有 `dependencies` 字段。
- [ ] 插件版本与契约版本范围均已声明，且范围写法合法（`>=1.0 <2.0` 形式）。
- [ ] 若使用 1.1 新增错误类别，`contract` 下限为 `>=1.1`。
- [ ] 若声明远端部署（`runtime.listen.port`）或使用 `config[]`，`contract` 下限为 `>=1.2`。
- [ ] 若声明 `config[]`：`key` 类型内唯一、`type` 合法、`secret: true` 时没有 `default`、`enum` 只与 `type: enum` 搭配。

## B. 能力（对应 [01](01-manifest.md) §3、[04](04-io-conventions.md)）

- [ ] 每个能力有唯一标识与明确语义描述。
- [ ] 每个能力有输入结构与输出结构定义（含必填/可选）。
- [ ] 能力不是「万能入口」（一个能力承载多种无关动作）。
- [ ] 声明了幂等性、并发约束、是否支持取消。
- [ ] 输入/输出的敏感性标记正确。
- [ ] 没有 `setup` / `version` 能力（命名禁令）。
- [ ] 不依赖 TTY 或任何交互输入；初始化幂等且无交互。
- [ ] 能力名末段为 `delete` / `restore` / `gc` 时已声明 `risk_level: destructive`。
- [ ] 高危能力的输入 schema 把确认字段列为 `required`（`delete` → `confirm_partition`；`restore`/`gc` → `confirm` + 目标字段）。
- [ ] 高危校验发生在任何副作用之前，且错误类别按 §3.5 区分（`input_invalid` / `validation_failed` / `precondition_failed`）。

## C. 通信（对应 [02](02-stdio-protocol.md) / [03](03-remote-protocol.md)）

- [ ] 命令式：stdin 读取至 EOF 后再执行；stdout 只输出结果；日志在 stderr。
- [ ] 命令式：单次调用只输出一份结果，不输出多份或空输出。
- [ ] 常驻：实现了版本查询、就绪探测、健康检查、优雅关闭。
- [ ] 常驻：未就绪时拒绝业务调用，而不是排队等待。
- [ ] **本机**常驻：只监听 `--ops-socket` 指定的路径，未监听 TCP 或其它路径。
- [ ] **远端**常驻：只监听 `--ops-config` 中 `listen.address` / `listen.port` 指定的地址，未监听其他地址。
- [ ] **远端**常驻：使用配置文件中的 `tls.cert_file` / `tls.key_file` / `tls.ca_file`，且校验客户端证书的期望底座标识。
- [ ] **远端**常驻：未自行生成/替换证书，未把私钥写入数据目录、日志或错误详情。
- [ ] **远端**常驻：已声明 `runtime.listen.port`；未声明则不得要求远端部署。
- [ ] 常驻：从 `--ops-config`、`--ops-data-dir` 读取路径，未依赖环境变量或 cwd。
- [ ] **本机**常驻：读取 `--ops-credential-file` 后立即删除，凭据只保存在内存。
- [ ] **远端**常驻：未依赖 `--ops-credential-file` 或 `--ops-socket`（远端不注入）。
- [ ] 常驻：忽略未知 `--ops-*` 参数与未知上下文字段。
- [ ] 常驻：未自带 systemd unit / pid 文件 / daemonize 逻辑。
- [ ] daemon 形态已明确「**只能经底座下发运行**」：未提供、也未引导用户手工部署二进制或注册 systemd unit。
- [ ] 未把**本机 daemon** 写成已支持：本机 daemon 托管当前**尚未实现**（OQ-044），本机实例应使用命令式形态。
- [ ] 两种形态：遵守底座下发的超时，超时后能中止。
- [ ] 不假设同一插件会被并发调用（底座一律串行，跨能力亦串行）。
- [ ] 不假设只有一个实例、不跨实例共享数据目录。

## D. 错误（对应 [05](05-errors-and-exit-codes.md)）

- [ ] 所有失败路径都映射到统一错误类别。
- [ ] 退出码与错误类别同桶（命令式）；未使用 9 及以上退出码。
- [ ] 常驻插件未用进程退出码表达业务结果。
- [ ] 业务语义问题用 `validation_failed` / `not_found` / `precondition_failed`，未混入 `input_invalid`。
- [ ] 错误详情不包含敏感信息。
- [ ] 结构不合法时**先拒绝**，不做部分执行。

## E. 日志（对应 [06](06-logging-observability.md)）

- [ ] 日志按约定输出到正确通道（stderr / 底座日志接口）。
- [ ] 日志包含必要上下文（能力标识、`invocation_id`、错误原因）。
- [ ] 没有凭据/令牌/私钥。
- [ ] 日志量可控（无循环内高频打印）。

## F. 版本与兼容（对应 [07](07-versioning-compatibility.md)）

- [ ] 契约版本范围与底座支持范围有交集（已核对）。
- [ ] 能忽略未知的可选字段与未知 `context` 字段（向前兼容）。
- [ ] 版本升级未改变已发布能力的语义（若改变，已新增能力或提升主版本）。

## G. 目录与资源（对应 [08](08-directory-layout.md)）

- [ ] 只写入被授权的数据目录，不写系统目录。
- [ ] 不读取其他插件数据目录。
- [ ] 临时文件可被清理，调用结束后无残留。
- [ ] 常驻插件未在包内或数据目录缓存凭据。
- [ ] **远端**：私钥/证书/配置文件权限符合 [08](08-directory-layout.md) §3.1（私钥 `0600`、配置文件 `0600`、状态目录 `0700`）。

## H. 安全

- [ ] 未声明权限的资源一律未访问。
- [ ] 不调用其他插件、不直连底座存储。
- [ ] 外部输入做了校验（防注入、防路径穿越）。
- [ ] 契约文件与生成代码来自底座 `sdk/`，未自行改写 `.proto` 或手写 RPC 桩。
- [ ] **远端**：不使用明文 TCP、不使用单向 TLS、不提供跳过客户端证书校验的开关。
- [ ] **远端**：只要能握手成功就接受调用之前，已完成「客户端标识 == 期望底座标识」校验。

## I. 契约完备性

- [ ] 实现过程中不存在「与底座口头约定」的行为；存在即说明规范有缺口。
- [ ] 所有用到的字段、错误码、退出码、路径、生命周期语义均能在本目录找到明文结论（必要时附底座规格的纯文本出处）。
- [ ] 若本轮新定了规则，已按 [AGENTS.md](AGENTS.md) §5 写回规范正文。
