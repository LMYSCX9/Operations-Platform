# PS-06 日志与可观测性约定

> 对应底座规格：`docs/06-non-functional-requirements.md` §4、§9、ADR-0011 ｜ 字段名：**待定（OQ-016）**

## 1. 日志输出位置

| 形态 | 输出位置 | 说明 |
| --- | --- | --- |
| 命令式插件 | stderr | 逐行输出；stdout 保留给结果 |
| 常驻插件 | 由底座注入的日志通道 | 若底座未注入，则输出到 stderr；具体方式待定 |

底座会把插件日志附加**插件标识 + 运行实例标识 + 调用标识**后统一输出，因此插件日志不需要重复打印这些标识，但**必须能与之关联**（见 §4）。

## 2. 级别

至少支持：`error`、`warn`、`info`、`debug`。

| 级别 | 使用场景 |
| --- | --- |
| error | 调用失败、依赖不可用、需要人工介入 |
| warn | 可恢复异常、降级、重试 |
| info | 调用开始/结束、关键状态变化 |
| debug | 排障细节（默认关闭） |

禁止把正常流程打成 error；禁止无级别日志。

## 3. 格式

- 单行一条，禁止多行日志（多行会被采集切碎）。
- 推荐结构化格式（键值对或 JSON）；最终格式**待定（OQ-016）**。
- 不以人类可读为唯一目标：字段必须可被机器提取。

## 4. 必带上下文

| 语义 | 说明 |
| --- | --- |
| 能力标识 | 本次日志属于哪个能力 |
| 阶段 | 接收 / 校验 / 执行 / 返回 |
| 结果 | 成功或错误类别 |
| 原因 | 失败时的简要原因 |

调用标识由底座提供，插件应在日志中携带（形式待定），以便跨宿主/插件关联。

## 5. 敏感信息（强制）

禁止出现在日志中的内容：

- 凭据、令牌、密码、私钥、证书私钥部分
- 完整的环境变量转储
- 完整的敏感输入/输出原文
- 个人身份信息（如无必要）

对于已标记为敏感的能力，日志只记录**存在性与摘要**（例如长度、哈希前缀）。

## 6. 日志量与性能

- 禁止在循环内逐条打印高频日志（应聚合或降级为 debug）。
- 单次调用日志条数应有上限意识；异常路径不得打印整个请求体。
- 日志写入不得阻塞业务主路径（若底座提供异步通道，按通道要求使用）。

## 7. 可观测性扩展（可选）

| 能力 | 是否必需 | 说明 |
| --- | --- | --- |
| 指标（调用次数/耗时/失败率） | 否 | 若底座提供，按约定暴露；不得阻塞调用 |
| 追踪 | 否 | v1 不承诺；调用标识可用于日志关联 |
| 自检信息 | 建议 | 版本、能力清单摘要可经版本查询接口获取 |

## 8. 反例清单

- 在 stdout 打印日志（命令式插件）→ 协议违规。
- `fmt.Println("start")` 这类无结构、无级别的输出 → 不可接受。
- 打印完整请求体（可能含凭据）→ 安全违规。
- 每条日志重复打印插件版本 → 噪声。
- 失败时只打印 `failed` 不打印原因 → 不可排障。

## 9. 待定项

| 主题 | 编号 |
| --- | --- |
| 日志字段名与格式 | OQ-016 |
| 常驻插件日志通道注入方式 | OQ-016 |

> 已定（底座 ADR-0005）：常驻插件经本机 UDS 与底座通信；日志不得混入 `InvokeResponse`，
> 统一在 stderr，或由底座注入的日志通道承载（注入方式待定，OQ-016）。
> **实现状态**：本机 daemon 托管当前尚未实现（OQ-044），本机请用命令式；远端 daemon 只能经底座下发运行，
> 日志由 systemd/journald 承载。
