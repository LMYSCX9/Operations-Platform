# DOC-10 定时任务规格

> 状态：`draft` ｜ 读者：底座开发、评审 ｜ 上游：[02 能力](02-foundation-capabilities.md) CAP-14、[ADR-0015](adr/0015-scheduler-implementation.md)、[03 插件模型](03-plugin-model.md)、[ADR-0007](adr/0007-persistence.md)、[ADR-0013](adr/0013-plugin-credential-encryption.md)
> 下游：[06 非功能要求](06-non-functional-requirements.md)、[07 开放问题](07-open-questions.md)

本文定义**定时任务的创建、触发、执行、记录与失败处置**。
**执行体固定为「调用某个插件的某个能力」，经 CAP-02 调用网关执行**，不是任意命令或脚本。
字段名、默认阈值、最小间隔、告警通道具体实现均**待定**，未定处标「待定」并引用开放问题编号。

## 1. 范围与边界

| 包含 | 不包含 |
| --- | --- |
| 任务定义的创建、修改、删除、启用/暂停 | 通用作业编排、DAG、任务依赖与分支 |
| 时间触发：cron 表达式、固定间隔 | 事件触发、消息队列触发、Webhook 触发 |
| 到点调用某个插件**实例**的某个能力 | 任意 shell / 脚本 / 命令执行 |
| 下次执行时间计算与展示 | 跨节点分布式调度与选主 |
| 手动立即执行所选实例的能力 | 面向目标主机的任意命令执行或下发（**未确认**，OQ-030） |
| 执行结果、记录、失败处置与告警 | 业务级任务模板（属于插件） |

**边界原则**：底座只提供「到点发起一次能力调用」的调度基础设施；任务成功与否以被调能力的返回为准，底座不解释业务结果。

## 2. 任务定义的组成（信息分组）

字段名与存储结构**待定**；以下信息组必须齐全：

| 信息组 | 内容 | 说明 |
| --- | --- | --- |
| 标识与描述 | 任务名称、唯一标识、说明 | 唯一标识规则待定 |
| 执行体 | 目标插件**实例**标识、目标能力标识 | 必须引用已安装实例上已声明的能力；不得填任意命令。**只给类型不给实例时拒绝**（[DOC-17](17-plugin-registry-and-configuration.md) §8） |
| 触发规则 | cron 表达式或固定间隔；时区 | 见 §3 |
| 执行参数 | 传给能力的参数集合 | **禁止明文凭据**，只能引用凭据库条目（§6） |
| 并发与超时 | 是否允许重叠、超时上限 | 默认不并发（§7） |
| 失败处置 | 重试次数、是否告警 | 默认值待定（OQ-035、OQ-033） |
| 状态 | 启用 / 暂停 / 已停用 | 见 §5 |
| 归属与审计 | 创建人、最后修改人、时间 | 变更必须留审计 |
| 运行态摘要 | 最近一次执行结果、下次执行时间 | 由调度器维护，不由用户直接编辑 |

要求：

- 任务定义只能指向**已安装且具备该能力声明**的插件实例；实例不可调用时任务标记为不可用；插件卸载或能力移除时任务不能继续静默运行（§9）。
- 一条任务定义只允许一种触发规则，不同时配置 cron 与固定间隔。
- 执行参数必须可校验；无法校验的参数不得保存。

## 3. 触发规则语义

| 编号 | 要求 |
| --- | --- |
| TASK-T-01 | 支持两种触发规则：**cron 表达式**与**固定间隔**；同一任务二选一 |
| TASK-T-02 | cron 语义（字段个数、是否支持秒、是否支持特殊字符）**待定**（OQ-031）；确认前不得实现秒级语义 |
| TASK-T-03 | 固定间隔必须有最小粒度下限；下限值**待定**（OQ-035） |
| TASK-T-04 | 时区处理：任务必须显式归属一个时区；未指定时使用服务进程时区还是固定时区**待定**；跨夏令时行为必须定义 |
| TASK-T-05 | 触发规则非法（语法错误、间隔过小、永不触发）时拒绝保存，不得保存后静默不执行 |
| TASK-T-06 | 修改触发规则后，下次执行时间必须立即重算；已认领未执行的历史触发不得回滚 |

## 4. 下次执行时间的计算与展示

| 编号 | 要求 |
| --- | --- |
| TASK-N-01 | 启用状态的任务必须能给出「下次执行时间」，并在 UI 与接口中展示 |
| TASK-N-02 | 暂停状态的任务不展示下次执行时间（或明确标注「已暂停」），避免误导 |
| TASK-N-03 | 计算必须基于任务时区，展示时同时给出时区，避免跨时区误读 |
| TASK-N-04 | 修改触发规则、恢复暂停、手动执行后，下次执行时间必须重新计算并落库 |
| TASK-N-05 | 「下次执行时间」是**计划值**，不代表精确触发时刻；精度容差待定（OQ-031、OQ-035） |

## 5. 启用、暂停与手动立即执行

| 编号 | 要求 |
| --- | --- |
| TASK-S-01 | 任务支持启用与暂停；暂停期间不产生新的触发 |
| TASK-S-02 | 恢复启用时不得补触发暂停期间错过的时点（除非错过执行策略另有规定，OQ-032） |
| TASK-S-03 | 删除任务必须二次确认；删除后不再触发，但历史执行记录按保留策略保留（§10） |
| TASK-S-04 | 必须支持「手动立即执行」：不改变触发计划，不重置下次执行时间以外的状态 |
| TASK-S-05 | 手动执行与定时执行使用同一执行路径、同一鉴权与审计，不允许出现「手动能跑、定时被拒」的语义分叉（授权模型差异除外，OQ-034） |
| TASK-S-06 | 暂停/启用/删除/手动执行都必须产生审计事件 |

## 6. 执行参数与凭据

| 编号 | 要求 |
| --- | --- |
| TASK-P-01 | 任务参数中**禁止**出现明文凭据（密码、私钥、令牌） |
| TASK-P-02 | 需要凭据时只能引用凭据库条目，由被执行插件在调用时按授权获取（ADR-0013、DOC-08 §2） |
| TASK-P-03 | 保存与修改任务时必须检测明显的凭据形态并拒绝；检测规则待定 |
| TASK-P-04 | 执行记录与日志不得回显参数中的敏感值；是否记录参数摘要待定 |
| TASK-P-05 | 任务参数不得作为绕过能力鉴权的手段：插件仍按声明能力与权限校验 |

## 7. 并发策略、超时与重试

| 编号 | 要求 |
| --- | --- |
| TASK-C-01 | **同一任务默认不并发**：上次执行未结束时，新的触发按重叠策略处置 |
| TASK-C-02 | 重叠处置候选：跳过本次并记录 / 排队等待 / 并行执行（**默认跳过并记录**，最终以用户确认为准，OQ-032 相邻条款） |
| TASK-C-03 | 不同任务之间可并行，但受全局并发上限约束（上限待定，OQ-035） |
| TASK-C-04 | 每次执行必须有超时；超时值可按任务配置，默认值待定（OQ-035） |
| TASK-C-05 | 超时必须终止等待并记录为失败类别「超时」，不得无限挂起 |
| TASK-C-06 | 重试仅针对可重试错误；重试次数、间隔与是否退避待定（OQ-035） |
| TASK-C-07 | 重试不得导致同一任务并行执行；重试期间该任务视为占用中 |

## 8. 失败处置与告警

| 编号 | 要求 |
| --- | --- |
| TASK-F-01 | 执行失败必须记录可区分的错误类别（超时、鉴权失败、插件不可用、参数错误、插件内部错误） |
| TASK-F-02 | 连续失败是否自动暂停任务**待定**；未定前不得自动暂停 |
| TASK-F-03 | 失败告警必须存在，通道**待定**（OQ-033：UI 通知 / 邮件 / Webhook / 外部告警系统） |
| TASK-F-04 | 告警内容不得包含凭据；应包含任务标识、插件与能力、失败类别、时间 |
| TASK-F-05 | 告警重复抑制策略待定，避免同一任务持续失败造成告警风暴 |

## 9. 错过执行的策略

**定义**：服务停机（或任务暂停后恢复、进程长时间阻塞）导致某个计划触发时点未被执行的，称为**错过执行**。

| 编号 | 要求 |
| --- | --- |
| TASK-M-01 | 启动时必须识别停机期间错过的触发点，不得静默当作「已跑过」 |
| TASK-M-02 | 补跑策略**待定**（OQ-032）：候选 A 不补跑、只记录错过；候选 B 合并补跑一次；候选 C 逐次补跑 |
| TASK-M-03 | 无论采用哪种策略，错过事实必须落记录并可查询，不允许完全无痕 |
| TASK-M-04 | 补跑不得造成同一任务并发；补跑量必须有上限（上限待定） |
| TASK-M-05 | 时钟向前跳变导致的「批量到期」不得形成突发风暴，必须有合并或限流保护 |

## 10. 调度器可靠性（单节点）

| 编号 | 要求 |
| --- | --- |
| TASK-R-01 | 任务定义与触发状态持久化：重启后任务**不丢失** |
| TASK-R-02 | 同一计划时点**不得重复触发**：触发认领必须先持久化，再执行 |
| TASK-R-03 | 不得**静默漏跑**：任何未执行、跳过、错过、失败的触发都要有记录 |
| TASK-R-04 | 崩溃恢复后，处于「已认领未完成」的执行必须被识别为中断，并按策略处理（标记失败或重试） |
| TASK-R-05 | 调度器不得因单个任务卡死而阻塞其他任务；执行必须异步化 |
| TASK-R-06 | 服务关闭流程中，调度器必须停止认领新触发，并给在途执行留出有界等待时间（时长待定，OQ-035） |

## 11. 变更、插件版本变更与卸载

| 编号 | 要求 |
| --- | --- |
| TASK-V-01 | 修改任务定义必须留审计并重算下次执行时间；不得影响正在执行的实例 |
| TASK-V-02 | 插件升级后，若目标能力仍存在且契约兼容，任务继续可用；兼容判定按 DOC-05 |
| TASK-V-03 | 插件升级导致能力移除或契约不兼容时，相关任务必须被标记为**不可用/需修复**，并停止触发，不得静默失败 |
| TASK-V-04 | 插件卸载/禁用时，其相关任务必须自动暂停并提示；不得继续触发 |
| TASK-V-05 | 插件恢复安装后，任务是否自动恢复启用**待定**（建议需人工确认） |
| TASK-V-06 | 任务引用的能力标识不存在时，保存与执行都必须给出明确错误，不得猜测替代能力 |

## 12. 执行记录与审计

| 编号 | 要求 |
| --- | --- |
| TASK-A-01 | 每次执行（含跳过、错过、超时、失败）生成一条执行记录，归属 [DOC-08](08-storage-and-data-directory.md) §2 的「执行与审计记录」分区 |
| TASK-A-02 | 执行记录至少包含：任务标识、插件与能力、计划时点、实际开始/结束、结果类别、耗时、触发方式（定时/手动/补跑） |
| TASK-A-03 | 任务定义的创建、修改、启用、暂停、删除、手动执行必须产生审计事件（CAP-05） |
| TASK-A-04 | 执行记录与审计采用批量写队列写入，不得每次触发直接抢写锁（DOC-08 §6） |
| TASK-A-05 | 保留期**待定**（OQ-016 一并确认）；到期清理不得影响审计的不可篡改要求 |

## 13. 权限

| 编号 | 要求 |
| --- | --- |
| TASK-SEC-01 | 创建、修改、删除任务属于受控操作，必须具备相应权限；默认拒绝 |
| TASK-SEC-02 | 权限粒度（按任务/按插件/按主机分组）**待定**，是否与 CAP-13 的主机授权模型共用体系**待定**（OQ-034） |
| TASK-SEC-03 | 「能创建任务」不等于「能调用任意能力」：执行时仍按 CAP-07 校验调用主体对目标能力的权限 |
| TASK-SEC-04 | 任务的操作者与实际执行主体必须可区分并记录，避免用任务身份绕过权限 |

## 14. 验收标准

1. 创建 cron 任务与固定间隔任务各一个，到点各触发一次，执行记录完整。
2. 重启进程后任务不丢失、不重复触发，下次执行时间正确。
3. 停机跨越多个触发点后，错过执行按已确认策略处理且留有记录。
4. 暂停任务后不再触发；恢复后不补触发暂停期间的时点。
5. 手动立即执行不改变计划，且与定时执行走同一鉴权与审计路径。
6. 同一任务执行未结束时再次到点，按重叠策略处置且有记录，不出现并行两份。
7. 任务参数写入明文凭据被拒绝；引用凭据库条目可正常保存。
8. 插件卸载后相关任务自动暂停；能力移除后任务标记为不可用。
9. 超时与失败产生可区分错误类别，并按已确认通道告警。
10. 所有任务变更均可在审计中还原「谁、何时、改了什么」。
