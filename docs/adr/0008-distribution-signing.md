# ADR-0008 插件分发格式与完整性/签名

- 状态：`proposed`
- 日期：2026-11-16
- 决策者：待定（用户）
- 关联：OQ-015、[DOC-04](../04-plugin-lifecycle.md) §3.2、[DOC-06](../06-non-functional-requirements.md) NFR-SEC-04

## 背景

插件需要从开发者的机器搬到生产环境。必须回答：分发物是什么形态、如何校验没被篡改、是否要求签名。
底座是单二进制，插件分发不应依赖在线市场或中心服务。

## 决策（待确认）

1. 插件包的文件形态。
2. 完整性校验强度（摘要 / 签名 / 两者）。
3. 是否支持在线获取（v1 倾向不支持）。

## 推荐方案与理由

**目录或 tar.gz 为分发物；SHA-256 摘要为必需校验；签名作为可选强度等级；v1 不做在线市场**

- 分发物：一个插件目录（含清单、可执行文件/服务描述、资源）或该目录的 tar.gz 归档。
- 完整性：清单或旁挂文件中提供内容摘要，底座安装时校验；不匹配即拒绝安装。
- 签名：可选。若启用，使用非对称签名（算法待定），底座内置受信公钥集合。
- 在线市场：不在 v1 范围（NG-3）；离线复制是主要路径。

理由：摘要能防传输损坏与低级篡改，实现成本低且无密钥管理负担；签名可以后置加强而不破坏已有机制度；离线分发符合运维现场的隔离网络现实。

## 备选方案

| 方案 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 摘要必需 + 签名可选（推荐） | 分级安全强度 | 渐进落地、离线友好 | 签名需密钥与分发管理 |
| B. 仅摘要 | 最低成本 | 实现简单 | 无法防伪造来源 |
| C. 签名强制 | 全部必须签名 | 供应链安全最强 | 内部开发流程负担重，密钥管理复杂 |
| D. 无校验 | 直接信任文件 | 无 | 违背 NFR-SEC-04，排除 |

## 影响

**正面**：安装即校验；拒绝损坏/被替换的包；签名可随安全要求逐步启用。

**负面 / 代价**：摘要需要随包维护（生成脚本/发布流程）；签名引入密钥轮换与受信公钥更新机制。

**迁移成本**：低（摘要→签名是增量）。

## 约束

- 摘要必须覆盖清单本身与所有可执行内容，避免「清单被换但内容不变」的绕过。
- 签名验证失败必须拒绝安装，不得降级为「仅记录告警」。
- 插件包内路径必须限制在包根目录内（防目录穿越，NFR-SEC-05）。
- 是否允许未签名插件在生产启用：待定（建议由配置开关控制，默认允许安装但可配置为仅允许已签名）。

## 验证方式

1. 修改插件包任一文件后安装被拒绝。
2. 签名不匹配（或公钥不匹配）被拒绝。
3. 包内包含 `../` 路径的条目被拒绝。

## 待确认问题

- 是否要求签名？签名算法与公钥分发方式？
- 未签名插件在生产是否允许启用？
