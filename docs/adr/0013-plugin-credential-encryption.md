# ADR-0013 插件外部凭据的静态加密

- 状态：`accepted`
- 日期：2026-11-16
- 决策者：用户（2026-11-16 确认）
- 关联：OQ-021（已关闭）、OQ-023（未闭合）、[DOC-08](../08-storage-and-data-directory.md) §2、[DOC-06](../06-non-functional-requirements.md) NFR-SEC-08、[ADR-0007](0007-persistence.md)、[ADR-0009](0009-configuration-model.md)、[ADR-0006](0006-plugin-authz.md)

## 背景

插件要访问外部中间件（数据库、消息队列、HTTP 接口等）时，需要持有对应的账号与密钥。这类凭据是**底座持久化三类数据中敏感级别最高的一类**（[DOC-08](../08-storage-and-data-directory.md) §2 C 类）：

- 一旦泄露，攻击者可越过底座直接操作被管系统；
- 底座的数据库是一个**本地单文件**，运维拷贝、备份、迁移都会带走库文件；
- 单节点部署（OQ-020）意味着没有额外的密钥基础设施可用，且必须保持单二进制、零外部服务依赖。

因此必须明确：凭据在库里以什么形式存在、密钥从哪来、这套方案能防住什么、防不住什么。

## 决策

**插件访问外部中间件的凭据使用 AES-256-GCM 对称加密后存库；主密钥来自环境变量（优先）或配置文件的独立字段，密钥本身不落库、不写入日志。**

| 决策点 | 结论 |
| --- | --- |
| 加密算法 | AES-256-GCM（认证加密，密文附带完整性校验） |
| 加密对象 | 只有「插件访问外部中间件的凭据」这类数据；不用于用户口令（口令用不可逆派生，见 OQ-037） |
| 主密钥来源 | 环境变量（优先）→ 配置文件独立字段；两者都没有时按配置非法处理 |
| 密钥存储 | **不落库**；不得写入日志、审计、错误详情、备份文件名 |
| 密钥派生 | 是否需要从口令派生主密钥（KDF）**待定**；确认前不得自行引入 KDF 参数 |
| 加密粒度 | 每条凭据独立随机 nonce；禁止复用 nonce（实现约束，非协商项） |
| 轮换与丢失 | **待确认（OQ-023）**；已知后果：主密钥丢失等于已存凭据不可恢复 |
| 具体算法参数、字段名、表结构 | 不在本 ADR 定义，随迁移脚本与配置项清单落地 |

选择「环境变量优先」的理由：容器与 systemd 都能注入环境变量，不需要把密钥写进任何持久文件；配置文件字段作为无环境变量注入能力时的退路。

## 防护边界（必须显式写入规格）

**能防住**：

- 数据库文件被单独拷走（备份泄露、误提交、临时目录残留、磁盘被离线读取）：没有主密钥，密文不可解。
- 备份文件被单独获取：备份中同样是密文。
- 日志、审计、错误详情、接口响应中的凭据泄露：凭据不进入这些通道。

**防不住**：

- **主机被完全控制**：攻击者能读到进程内存与环境变量，也就能取得主密钥，从而解密全部凭据。
- 运行期被注入或调试（内存转储、ptrace、调试端口暴露）。
- 拥有服务账号权限的人直接调用底座接口读取/使用凭据（取决于授权模型，见 ADR-0006）。
- 主密钥本身被明文写入环境变量文件、启动脚本或容器编排文件并被读取。

结论：这是**静态数据保护**方案，不是**运行期隔离**方案。不得在文档或 UI 中把「加密」表述为「主机被攻破时凭据仍安全」。

## 备选方案与放弃原因

| 方案 | 说明 | 放弃原因 |
| --- | --- | --- |
| A. AES-256-GCM + 本地主密钥（本次选定） | 对称加密，密钥来自 env / 配置文件 | 满足「基础方案」诉求，零外部依赖，实现成本最低 |
| B. 外接密钥服务（KMS / Vault 等） | 密钥托管在外部服务 | 引入外部服务依赖，破坏单二进制与离线部署；留作后续演进（OQ-021 已关闭，如需再开新 ADR） |
| C. 明文存库 + 依赖文件权限 | 不做加密 | 库文件或备份被拷走即泄露，不可接受 |
| D. 每条凭据用独立密钥并层层封装 | 更细的密钥层级 | 根密钥仍要落在同一台主机上，安全收益有限，复杂度显著上升 |

## 影响

### 正面

- 库文件与备份脱离主机后不可直接读出凭据，降低拷贝类泄露的实际危害。
- 不引入外部服务，保持单二进制、离线可部署。
- 凭据使用路径集中：只有宿主进程在调用时解密，插件拿不到底座的解密能力。

### 负面 / 代价

- 主密钥成为**新的关键资产**：丢失即凭据不可恢复，泄露即全部凭据失效（轮换方案见 OQ-023）。
- 启动强依赖密钥可用性：缺少主密钥时，凡涉及凭据的功能都必须明确失败，不能降级为明文。
- GCM 对 nonce 复用零容忍，实现必须保证每条记录独立随机 nonce。
- 无法防御主机被完全控制（见防护边界）。

### 迁移成本

- 若未来改为外部密钥服务，需引入密钥提供者抽象并重加密存量数据；当前**不做**多后端抽象。
- 主密钥轮换需要「解密—重加密」流程，OQ-023 关闭前不实现自动轮换。

## 约束（实现必须遵守）

1. 主密钥**不得**写入数据库、日志、审计事件、错误详情、备份文件名与任何接口响应。
2. 缺少主密钥时，涉及凭据读写的能力必须**显式失败**，禁止以明文降级运行。
3. 每条凭据使用独立随机 nonce，禁止复用；禁止自行实现加密模式。
4. 解密只在调用外部系统前发生，作用域限定在当次调用；不得提供明文导出接口。
5. 用户口令不使用本方案，必须使用不可逆派生（[DOC-08](../08-storage-and-data-directory.md) §2 A 类）。
6. 配置文件中主密钥字段的**具体名称**待定，随配置项清单落地（ADR-0009）；文档与模板中不得预写字段名。
7. 备份与恢复必须保持密文原样，不得在备份流程中解密（[DOC-08](../08-storage-and-data-directory.md) §7）。

## 验证方式

1. 无主密钥启动时，涉及凭据的功能返回明确错误，服务不进入「明文可用」状态。
2. 直接打开库文件无法读出任何凭据明文；备份文件同样不含明文。
3. 日志、审计、错误详情与接口响应中检索不到凭据与主密钥。
4. 同一条凭据多次写入产生不同密文（nonce 不复用）。
5. 篡改密文任一字节后解密失败（GCM 完整性校验生效），且错误不泄露明文内容。
