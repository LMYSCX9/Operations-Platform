# ADR-0009 配置模型（来源、格式、优先级）

- 状态：`proposed`（其中「数据目录来源」与「主密钥来源」两项已于 2026-11-16 由用户确认，见 §已确认部分）
- 日期：2026-11-16
- 决策者：待定（用户）
- 关联：OQ-008、OQ-022（默认数据目录回退，未闭合）、[ADR-0007](0007-persistence.md)、[ADR-0013](0013-plugin-credential-encryption.md)、[DOC-06](../06-non-functional-requirements.md) §5、CAP-03

## 背景

底座需要可配置：监听地址、数据目录、插件目录、日志级别、鉴权参数等。必须确定来源与优先级，否则部署行为不可预测。
**具体配置项清单尚不存在**，本文不定义字段，只定义机制。

## 决策（待确认）

1. 配置来源与优先级。
2. 配置文件格式与位置。
3. 是否支持热加载。
4. 密钥类配置的处理方式。

## 推荐方案与理由

**文件 + 环境变量 + 命令行，优先级 命令行 > 环境变量 > 配置文件；格式建议 YAML；启动时一次性加载**

- 优先级：命令行 > 环境变量 > 配置文件 > 内置默认值。命令行用于临时覆盖，环境变量用于容器注入，文件用于持久配置。
- 格式：YAML（可读性好、注释友好）；JSON 作为备选。
- 加载：启动时一次性加载并校验，**非法即启动失败**（NFR-RUN-01）。
- 热加载：v1 不支持，配置变更需重启，避免运行期状态不一致。
- 目录：配置目录、数据目录、插件目录、日志输出均可由配置指定，默认值待定。
- 密钥：配置文件只存放「密钥引用」（如环境变量名/文件路径），禁止明文写入配置文件。

理由：这套优先级是运维与容器场景的通行做法；一次性加载与「非法即失败」能显著降低排障成本；密钥分离是安全底线。

## 已确认部分（用户 2026-11-16）

以下两项已由用户拍板，不再作为待确认项；其余机制仍为 `proposed`。

| 决策点 | 结论 |
| --- | --- |
| 数据目录来源 | **由配置文件指定**，路径可配置；不接受隐式猜测 |
| 数据目录路径约束 | 必须为**绝对路径**；**不得指向网络文件系统**（NFS/SMB/FUSE/同步盘），启动时必须校验 |
| 默认回退 | 配置文件未指定时的回退位置 **未确认（OQ-022）**；候选为操作系统惯例路径（Linux `/var/lib/`、Windows `C:\ProgramData\`）。确认前**不得**硬编码任何默认路径 |
| 主密钥来源 | 环境变量（优先）→ 配置文件独立字段；密钥不入库、不写日志，见 [ADR-0013](0013-plugin-credential-encryption.md) |
| 主密钥字段名 | **待定**，随配置项清单落地；文档与模板中不得预写 |

由数据目录派生的约束：便携部署通过在该配置文件中指定不同的数据目录实现；是否额外提供命令行覆盖参数**未确认**，在配置项清单落地前不得写入规格。

## 备选方案

| 方案 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 文件+env+命令行（推荐） | 三级来源 | 部署灵活、行为可预期 | 需要明确展示「最终生效配置」 |
| B. 仅配置文件 | 单一来源 | 简单 | 容器注入不便 |
| C. 外部配置中心 | 集中管理 | 多实例统一 | 违背单二进制/离线定位，排除 |
| D. 支持热加载 | 运行期变更 | 无需重启 | 状态一致性复杂，v1 不需要 |

## 影响

**正面**：部署方式统一；配置错误在启动时暴露；容器化友好。

**负面 / 代价**：多来源会带来「为什么值不是我预期的」问题，需要提供「打印最终生效配置（脱敏）」的能力。

**迁移成本**：低。配置项清单后续补入，不影响机制。

## 约束

- 所有配置项必须有默认值或明确标记必填；不得存在隐藏必需项（NFR-CFG-03）。
- 必须提供「打印最终生效配置」能力，且对密钥类字段脱敏。
- 配置项清单在实现前必须写入 [DOC-06](../06-non-functional-requirements.md) 或独立配置参考文档，**不得散落在代码中**。
- 插件配置与底座配置分离：插件配置归属与下发方式见 OQ-008 / EP-03。

## 验证方式

1. 同一配置项在三级来源同时存在时，取值符合优先级。
2. 非法配置值导致启动失败并明确指出哪一项。
3. 日志与自检输出中不出现密钥明文。

## M0 实现基线（待确认）

M0 骨架已按本 ADR 的推荐优先级落地最小配置集。以下取值属于实现期基线，
**不改变本 ADR 的 `proposed` 状态**，统一登记为 [OQ-036](../07-open-questions.md)：

| 键名 | 环境变量 | 命令行 | 必填 | 默认值 |
| --- | --- | --- | --- | --- |
| `data_dir` | `OPS_PLATFORM_DATA_DIR` | `-data-dir` | 是 | 无（未配置即启动失败，不猜默认路径，OQ-022） |
| `listen_addr` | `OPS_PLATFORM_LISTEN_ADDR` | `-listen` | 是 | 无 |
| `log_level` | `OPS_PLATFORM_LOG_LEVEL` | `-log-level` | 否 | `info` |
| `shutdown_timeout` | `OPS_PLATFORM_SHUTDOWN_TIMEOUT` | `-shutdown-timeout` | 否 | `10s` |

- 配置文件格式：M0 曾采用 **JSON**（本 ADR 备选方案）；**M1 起改为 YAML**，随 [ADR-0016](0016-yaml-and-json-schema-dependencies.md) 引入 `gopkg.in/yaml.v3`，与插件清单复用同一依赖。本 ADR 的 `proposed` 状态不因此改变。
- 配置文件位置：只支持 `-config <path>` 显式指定，不设隐式搜索路径。
- 未知配置字段：启动失败，避免键名拼写错误被静默忽略。
- M1 扩展的配置键（插件运行时、批写队列）见 [DOC-12](../12-m1-plugin-runtime.md) §2，登记为 OQ-039。
