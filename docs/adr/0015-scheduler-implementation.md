# ADR-0015 定时任务调度器的实现方式

- 状态：`proposed`
- 日期：2026-11-16
- 决策者：待定（用户）
- 关联：OQ-030~OQ-035、[DOC-10](../10-scheduled-tasks.md)、CAP-14、CAP-02、CAP-10、[ADR-0007](0007-persistence.md)

## 背景

用户要求底座提供「定时任务」：按时间规则调用某个插件的某个能力。

这带来一个必须显式裁决的问题：**谁来计时、谁来决定「该跑了」**。候选差异很大，且直接决定部署形态（是否需要额外进程/服务）、可靠性边界（停机期间错过怎么办）与运维成本。

需要同时承认的边界：

- v1 定时任务的执行体是「调用插件能力」，走既有调用网关 CAP-02，**不是**任意命令执行。
- 默认在**本机**执行；能否面向目标主机（复用 CAP-13 下发通道）尚未确认（OQ-030）。
- 底座是单节点、单二进制、嵌入式 SQLite（ADR-0007），没有外部消息队列或协调服务。

## 决策（待确认）

1. 调度器是进程内组件，还是独立的外部调度系统。
2. 触发时间如何计算与持久化，重启后如何恢复。
3. 错过执行、重复触发、时钟变化如何处置。

## 推荐方案

**进程内调度器 + 任务定义持久化到库 + 单写者驱动的触发认领。**

| 决策点 | 推荐 | 理由 |
| --- | --- | --- |
| 调度位置 | 底座进程内（与 CAP-02 同进程） | 符合单二进制与单节点；无需额外组件；任务触发与调用网关零跨进程开销 |
| 任务持久化 | 任务定义与「下次执行时间」落库（CAP-10） | 重启不丢任务；与审计、执行记录同库，便于追溯 |
| 触发认领 | 单写者模型下由宿主认领到期任务，写入「已认领」事实后再执行 | 单节点下天然去重；避免同一任务被重复触发 |
| 计时方式 | 内部定时器 + 到期扫描兜底（具体周期待定） | 纯定时器在休眠/时钟跳变下不可靠，扫描兜底可自愈 |
| 进程外依赖 | 无 | 保持单二进制、离线可部署 |
| 执行方式 | 通过 CAP-02 调用目标插件能力 | 复用鉴权、超时、错误归一与审计，不另建执行通道 |

不采用「每个任务起一个独立进程/协程长期计时」的做法作为唯一机制：任务数量增长后资源不可控，且重启后状态难以对齐。

## 备选方案与放弃原因

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. 进程内调度（本次推荐） | 底座自带调度循环与持久化任务表 | 采用 |
| B. 外部调度系统 | 独立部署调度服务，通过接口触发底座 | **不采用为 v1 基线**：引入外部服务与第二套高可用问题，破坏单二进制与离线部署；多节点时再评估 |
| C. 依赖操作系统 cron / systemd timer | 由宿主 OS 触发 | **不采用**：跨平台不一致（Windows/macOS 差异大）、任务定义分散、变更需操作宿主、审计与权限边界无法统一 |
| D. 混合：进程内为主，外部系统可触发 | 保留外部触发入口 | 作为演进方向；v1 不实现，避免提前抽象 |

## 影响

### 正面

- 零外部依赖，随单二进制交付；任务定义、执行记录、审计同库，排障路径短。
- 复用 CAP-02 的鉴权与错误归一，定时调用的行为与手动调用一致，减少两套执行语义。
- 重启恢复只需读库重算下次执行时间，不依赖外部状态。

### 负面 / 代价

- 调度器与业务进程同生命周期：进程停机期间不会触发（错过执行策略见 OQ-032）。
- 单节点单写者意味着**无法水平扩展调度能力**；多节点高可用仍是远期 idea（DOC-00 IDEA-7）。
- 系统时钟回拨/跳变、长任务占用、任务数量增长都需要额外保护（重叠策略、上限待定）。
- 精度受扫描周期与进程调度影响；「准时」只能承诺到某个容差，具体容差待定（OQ-031、OQ-035）。

### 迁移成本

- 若未来改为外部调度系统，任务定义与执行记录可复用，触发层需替换；当前**不做**多后端调度抽象。
- 若支持多节点，需要引入分布式认领与一致性机制，属于新 ADR 范畴。

## 约束

1. 触发必须「先持久化认领、后执行」；不得在内存里只记状态就调用，避免重启后重复或丢失。
2. 同一任务默认不并发；重叠处置策略未定前，按「跳过本次并记录」处理（OQ-032 相邻条款）。
3. 任务参数**禁止**明文凭据，只能引用凭据库条目（ADR-0013、DOC-10 §6）。
4. 执行必须走 CAP-02，不得绕过鉴权、超时与审计。
5. 调度器不得提供任意 shell/脚本执行入口（DOC-02 CAP-14 边界）。
6. 错过执行的补跑策略、告警通道、时区与秒级支持均待定，未定前不得硬编码（OQ-031、OQ-032、OQ-033）。
7. 不引入具体第三方调度库；选型与版本在实现阶段确定。

## 验证方式

1. 创建任务后重启进程，任务仍在且下次执行时间被正确重算。
2. 同一任务在到点时只被执行一次；人为制造并发触发不产生重复执行记录。
3. 服务停机跨越多个触发点时，行为符合已确认的错过执行策略（不静默、不重复）。
4. 长任务超过下次触发时间时，按重叠策略处理并留痕，不出现同一任务并行两份。
5. 系统时间被向前/向后调整后，调度器不产生爆发式补跑或永久错位（容差待定）。
6. 任务参数中尝试写入明文凭据时被拒绝，只能引用凭据条目。
7. 定时调用与手动调用的鉴权、超时、错误类别一致。
