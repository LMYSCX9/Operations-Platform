# ADR-0002 前端技术栈与 UI 宿主形态

- 状态：`proposed`
- 日期：2026-11-16
- 决策者：待定（用户）
- 关联：OQ-013、OQ-011、[ADR-0025](0025-plugin-provided-ui.md)、[DOC-02](../02-foundation-capabilities.md) CAP-08

## 背景

底座需要 Web UI（登录、导航、插件能力入口）。前端技术栈未定；同时需回答「插件能否向前端贡献界面」。
后者直接决定前端架构（是否需要微前端/插槽机制），必须在架构阶段就明确边界。

## 决策（待确认）

1. 前端框架与构建工具链。
2. UI 形态：单页应用（SPA）还是服务端渲染（SSR）。
3. v1 是否支持插件贡献界面。

## 推荐方案与理由

**SPA + TypeScript + 主流组件框架；v1 不支持插件界面**

- SPA 与「后端提供 API、前端静态内嵌」最契合，构建产物是纯静态资源，便于 embed。
- TypeScript 提供契约类型安全（后端接口类型可生成）。
- v1 不支持插件界面：避免在插件契约尚未稳定时引入前端扩展协议（INV/EP-05 仍为 idea）。

**注意**：具体框架（React / Vue / Svelte 等）属于用户偏好，ADR 不代为定稿，需用户拍板（OQ-013）。

## 备选方案

| 方案 | 说明 | 评价 |
| --- | --- | --- |
| A. SPA（推荐） | 纯静态产物 + API | 与单二进制内嵌天然匹配 |
| B. SSR | Go 模板或 Node 渲染 | 引入 Node 运行时或模板复杂度，违背单二进制简洁性 |
| C. 服务端模板 + 少量 JS | Go html/template | 简单但交互能力弱，插件能力入口扩展困难 |
| D. 支持插件界面（微前端/iframe） | 插件提供独立前端 | 二档「自带前端包」记 idea 并挂起（OQ-011）；一档声明式界面另见 [ADR-0025](0025-plugin-provided-ui.md)（proposed） |

## 影响

**正面**：构建产物简单；与 ADR-0001 的内嵌方式直接配合；UI 与 API 解耦。

**负面 / 代价**：需要 Node 工具链参与构建（仅构建期，运行期无依赖）；SPA 首屏依赖 API。

**迁移成本**：若后续要支持插件界面，需要新增前端扩展协议与加载机制，属于较大改动，故建议现在就锁定「v1 不支持」。

## 约束

- 前端不得直接访问插件；所有调用经底座接口层（INV-2）。
- 前端静态资源必须可被 embed，禁止构建产物放在二进制之外作为必需依赖。
- 插件界面若未来引入，必须走新 ADR，并定义隔离（iframe/沙箱）与权限模型。

## 验证方式

- UI 构建产物可被嵌入并正常加载。
- 断网环境下 UI 可用（不依赖 CDN）。
