# ADR-0006 插件鉴权与授权模型

- 状态：`accepted`（2026-11-16 修订：远端调用以 mTLS 证书作为传输层身份，授权模型不变）
- 日期：2026-11-16（定稿）
- 决策者：用户（P0 六项批准；本轮确认远端证书不代表授权）
- 关联：OQ-003（decided）、OQ-010/OQ-027（decided）、OQ-047、[DOC-03](../03-plugin-model.md) §6、[DOC-02](../02-foundation-capabilities.md) CAP-07、[ADR-0005](0005-daemon-rpc-transport.md)、[ADR-0013](0013-plugin-credential-encryption.md)、[ADR-0022](0022-remote-plugin-pki-and-mtls-certificates.md)

## 背景

插件是独立进程，且视为不可信。底座需要回答两类问题：

1. **谁在调用**（用户身份 / 系统身份）——决定能否放行。
2. **插件能碰什么**（插件权限）——决定插件能访问哪些资源。

两类问题不能混为一谈：用户身份解决「能否触发能力」，插件权限解决「插件执行时能访问什么」。

## 决策

**宿主签发短期凭据 + 能力级授权 + 默认拒绝；权限声明采用「资源类别 + 动作」语义；审计记录授权结果。**

### 1. 调用主体（用户侧）

- 用户在 UI 登录后获得会话，每次调用在网关处解析主体与角色。
- 是否区分角色（如管理员/操作员/只读）以及人类身份源（本地账号 / 外部 IdP）**仍未定**（OQ-037）；
  在定稿前，v1 至少要求「已认证主体」才能调用，未认证一律拒绝。

### 2. 插件身份与通道身份

插件身份分两层，**不得混为一谈**：

**（1）本机形态：启动期短期凭据**

- 宿主在启动插件时**签发短期凭据**：仅存于内存、可轮换、进程退出即失效；**不落盘、不写日志**。
- 插件访问底座能力（配置读取、数据目录、凭据库等）时必须携带该凭据，底座校验后按清单权限放行。
- 凭据过期后插件重新获取；重新获取机制属实现细节，不得引入长期共享密钥。

**（2）远端形态：双向 TLS 证书**

- 调用链路的**通道身份**由 mTLS 承担：底座以客户端证书证明「我是哪个底座节点」，插件以服务端证书证明「我是哪个插件、在哪台主机」。
- 两侧都校验到内置 CA 的链、EKU、CN/SAN 与有效期，并检查序列号吊销名单（[ADR-0022](0022-remote-plugin-pki-and-mtls-certificates.md)）。
- 远端**不**注入启动期一次性凭据文件；`context.credential` 可携带但**不是**远端调用的身份依据。
- 远端插件访问底座能力的通道 v1 不开放；若将来开放，必须使用证书 + 能力级授权并另立 ADR。

### 2.1 证书不等于授权

| 规则 | 说明 |
| --- | --- |
| 证书只证明「你是谁」 | 有效证书仅说明对端是「某底座节点」或「某插件」，不附带任何能力许可 |
| 授权始终在底座网关 | 主体 → 能力的判定、默认拒绝、审计（§3~§5）不因 mTLS 而改变或放宽 |
| 两层叠加而非替代 | 先完成 TLS 通道身份校验，再完成主体认证与能力授权；任一层失败都拒绝 |
| 证书被吊销/过期 | 在握手阶段失败，调用方得到可诊断的连接错误，不会进入授权判定，也不会被当作「无权限」 |
| 插件侧不得放行 | 插件只能校验「调用方是期望的底座节点」，不得据此推断某能力被授权；授权结论由底座携带/执行 |
| 跨主机不改变授权 | 远端调用的主体、能力、审计与本地调用完全一致，不因「来自网络」而降级或提权 |

**新增约束**：插件必须校验客户端证书的底座标识与配置文件中的期望值一致；底座必须校验服务端证书的插件标识与主机标识；
两侧均不得提供「跳过校验」的配置项。

### 3. 授权粒度

- **能力级**：能否调用某个能力（主体 → 能力）。
- **资源类别 + 动作**：插件声明所需资源能力，语义为「对哪类资源、允许哪些动作」。

| 资源类别 | 可用动作（语义） | 说明 |
| --- | --- | --- |
| `config` | `read` | 读取**自身**配置，不可读其他插件配置 |
| `data_dir` | `read` / `write` | 读写**自身**数据目录 |
| `network` | `connect` | 访问外部服务；是否按域名/IP 白名单限制待定 |
| `filesystem` | `read` / `write` | 访问数据目录以外的指定路径，属高风险，须逐项声明 |
| `credential` | `use` | 引用凭据库条目（**不得**取回明文） |
| `invoke_plugin` | `call` | 调用其他插件能力，**v1 禁止**（INV-7），保留枚举仅为显式拒绝 |

- 类别枚举属契约；新增类别属 MINOR，删除或改语义属 MAJOR（[DOC-05](../05-extension-points-and-compatibility.md) §4）。
- 是否按范围（路径/域名的 `scope`）进一步收窄，v1 允许声明 `scope`，但底座是否强制校验范围待定（OQ-037）。

### 4. 默认拒绝

- 未在清单声明的资源类别与动作**一律不可用**（INV-1）。
- 未认证主体、未授权能力、未声明资源，三者都返回可区分错误，不返回「泛化拒绝」。

### 5. 审计

- 每次授权判定必须留审计：**主体、插件标识、能力/资源、动作、判定结果（允许/拒绝）、原因、时间**。
- 审计字段清单仍待定（OQ-016），但上述语义项为**必需**。

### 6. 凭据与敏感信息

- 插件凭据（短期令牌）不得写入日志、审计或磁盘明文。
- 静态存储的外部凭据必须加密：AES-256-GCM 密文存库，主密钥不入库、不写日志（[ADR-0013](0013-plugin-credential-encryption.md)）。
  该措施只防「库文件被单独拷走」，**不防主机被完全控制**。
- 凭据的读取与使用必须经授权判定并留审计；**不得提供明文导出接口**。
- 插件不得自行提升权限；权限变更必须经底座并留审计。
- 远端插件私钥与密钥材料：私钥 `0600`、状态目录 `0700`，不得写入日志/审计/崩溃转储；审计只记录证书序列号与指纹（[ADR-0022](0022-remote-plugin-pki-and-mtls-certificates.md) §6）。

## 被否方案与原因

| 方案 | 说明 | 否决原因 |
| --- | --- | --- |
| 静态共享密钥 | 配置约定一把密钥 | 轮换困难、易泄漏、无法细粒度授权、无法回答「谁调用了什么」 |
| mTLS 双向证书作为**唯一**身份与授权依据 | 证书即身份、证书即权限 | 证书只能证明对端，不能表达「主体能否调用某能力」；且本机形态无网络面，统一用证书反而增加运维负担。**现状**：远端以证书作为通道身份，授权仍由能力级模型承担 |
| 无鉴权（信任本机文件权限） | 零成本 | 不满足审计与最小权限要求（INV-1、NFR-SEC-06） |
| 全有全无授权（插件级开关） | 只判「插件是否可信」 | 无法满足最小权限，一个能力越权即全插件越权 |
| 资源路径级白名单作为 v1 基线 | 精确控制 | 声明与维护成本高，且与插件可移植性冲突；保留 `scope` 字段但不强制 |

## 影响与约束

**正面**：权限模型成为契约的一部分，插件开发期即可声明；审计可回答「谁调用了什么、是否被拒绝」；
短期凭据避免长期密钥的轮换难题。

**负面 / 代价**：需实现凭据签发/校验与授权判定；清单复杂度上升；类别过粗会限制插件，过细会增加维护成本。

**实现约束**：

- 鉴权失败必须区分「未认证」与「无权限」两类错误。
- 授权判定必须在网关（CAP-02）集中完成，插件侧不得自行放行。
- 插件能力的定时任务触发（CAP-14）同样走该授权模型，不因「系统触发」而隐式放行。

## 验证方式

1. 未声明 `network` 的插件发起出站连接 → 被拒绝且审计记录原因。
2. 插件尝试读取其他插件数据目录 → 被拒绝（INV-7 与资源类别双重拦截）。
3. 使用过期凭据调用 → 返回「未认证」类错误，插件可重新获取后重试。
4. 已认证但无该能力权限的主体调用 → 返回「无权限」，与未认证可区分。
5. 每次授权判定在审计中可查，且不含凭据明文。
6. 定时任务触发的调用被拒绝时，审计中可区分「系统触发 + 无权限」。
7. 远端使用有效证书但主体无该能力权限 → 返回「无权限」，与证书无效（握手失败）可区分。
8. 远端证书被吊销 → 在握手阶段失败，不产生授权审计中的「允许」记录。
9. 远端插件收到来自非期望底座标识的客户端证书 → 拒绝连接，不进入 `Ready`。
