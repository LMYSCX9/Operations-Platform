# ADR-0025 插件界面承载模型（v1 仅声明式界面）

- 状态：`proposed`（v1 只做声明式界面的方向已由用户确认；一档的能力边界与展示边界仍待 OQ-011）
- 日期：2026-11-17
- 决策者：用户（v1 仅一档「声明式界面」；二档「插件自带前端包」挂起，不进入 v1）
- 关联：OQ-011（重新开启）、OQ-013、[ADR-0001](0001-single-binary-embedding.md)、[ADR-0002](0002-frontend-stack.md)、[ADR-0003](0003-plugin-discovery-registration.md)、[ADR-0006](0006-plugin-authz.md)、[ADR-0021](0021-capability-execution-and-destructive-confirmation.md)、[ADR-0023](0023-plugin-registry-instances-and-configuration.md)、[DOC-02](../02-foundation-capabilities.md) CAP-08、[DOC-05](../05-extension-points-and-compatibility.md) EP-05、[DOC-16](../16-web-ui-m5.md)、[plugin-spec/12](../../plugin-spec/12-plugin-ui.md)
- 实现：无。本 ADR 只写草案与边界，不含实现代码；未定字段名、控件集合与接口一律标 OQ

## 背景

插件能力差异极大：有的只做只读查询，有的需要多步表单，有的结果是一张大表，有的是一段诊断报告。若底座前端把每个插件的页面都硬编码进去，插件越多、变更越频繁，前端越难维护，也把「业务功能归插件」的边界重新破坏掉。

参考对象是 DBX 一类工具：插件包内自带前端资源，运行在沙箱 iframe 中，通过 Host API 与宿主通信。该模型在插件侧体验统一、扩展成本低。

但两者风险等级不同：

| 维度 | DBX 类本地桌面工具 | 本仓库（多主机运维底座） |
| --- | --- | --- |
| 部署与用户 | 本地桌面、通常单用户 | 集中式 Web 管理端，多用户、多角色 |
| 持有资产 | 本机资源 | **生产机 SSH 凭据、插件证书私钥、mTLS 客户端身份、底座会话** |
| 第三方代码后果 | 影响本机 | 一旦沙箱失效即可触达管理端全部权限，直接影响生产机 |
| 供应链 | 用户自行安装 | 插件可能来自外部或内部多个团队，审核能力有限 |

因此不能把「插件自带前端」当作默认能力直接引入。本 ADR 只确认一件事：**v1 采用不引入第三方前端代码的声明式界面**；自带前端包挂起，不作为 v1 的既定方向，也不承诺「未来必然要做」。

**远端插件不改变该模型**：界面资源（若将来存在）随插件包留在底座侧、由底座托管，浏览器只与底座通信，不直连目标机。远端插件影响的是后端调用传输（见 [ADR-0005](0005-daemon-rpc-transport.md)、[ADR-0018](0018-daemon-process-custody-and-injection.md)、[ADR-0022](0022-remote-plugin-pki-and-mtls-certificates.md)），与界面承载无关；目标机不提供、也不得提供任何前端资源。

## 决策（待确认）

**v1 只采用一档「声明式界面」：插件在清单中声明配置项与结果的展示方式，由底座用自有组件统一渲染，不加载任何插件提供的代码。二档「插件自带前端包」挂起为 idea，不进入 v1 范围。**

### 1. 一档：声明式界面

#### 1.1 定义与边界

- 插件只**声明**：有哪些配置项、如何分组与排序、结果如何呈现、从哪个入口进入。
- 底座只**渲染**：用自身组件库生成表单、只读展示与结果视图；插件不提供 HTML、JS、CSS，也不提供可执行内容。
- 声明是**数据**，不是模板语言：不支持条件表达式、循环、脚本、内联样式、外链资源。
- 声明随插件包与清单一起校验；校验失败按 [ADR-0003](0003-plugin-discovery-registration.md) 处理（拒绝安装并给出可定位原因），不得「降级成半个页面」。

**不做的事**：不执行插件代码、不挂载插件 DOM、不引入 iframe 承载插件页面、不允许插件覆盖底座导航与登录流程。

#### 1.2 声明内容（语义分组，字段名待 OQ-011）

| 分组 | 声明什么 | 边界 |
| --- | --- | --- |
| 入口 | 在底座导航中的显示名、所属分组、所需能力 | 只能指向已声明的能力；不得声明任意 URL 或外部链接 |
| 配置表单 | 由 [ADR-0023](0023-plugin-registry-instances-and-configuration.md) 的 `config[]` 派生；可补充分组、顺序、帮助文本、占位提示 | 控件类型限定为底座内置集合（文本、多行文本、数字、布尔、枚举、敏感值）；不得声明自定义控件 |
| 动作 | 哪个能力对应哪个按钮/提交入口、需要哪些参数 | 参数结构以能力 schema 为准；不得绕过 CAP-02 网关 |
| 结果展示 | 选择底座内置的展示形态（表格、键值、纯文本/预格式化、结构化 JSON）与字段顺序 | 展示形态是**有限枚举**；不支持任意图表 DSL、不支持内联脚本、不支持远程图片 |
| 说明 | 页面标题、说明文字、空状态与错误提示文案 | 纯文本；不渲染 HTML |

规则：

- 声明只能**收窄**展示方式，不能扩大能力：未在清单声明的能力不得因界面声明而出现。
- 未识别的控件或展示类型：底座降级为「原始 JSON + 只读文本」并记录告警；不得执行未知内容。
- 字段名、枚举取值与校验规则属实现基线，未确认前一律标 OQ-011，不得在插件文档中写死。

#### 1.3 渲染与结果表达

- 底座按声明渲染；同一份声明在不同实例上只改变数据（实例配置、调用结果），不改变结构。
- 结果展示以底座统一组件呈现；插件只提供数据，不提供样式与布局。
- 分页、排序、列宽、导出等能力由底座统一提供，插件不能自定义交互逻辑。
- 「是否允许自定义展示顺序」与「支持的结果形态清单」为 OQ-011 待定项。

#### 1.4 权限与高危确认

- 界面可见性以**当前用户已被授权的实例与能力**为准；默认拒绝不变（[ADR-0006](0006-plugin-authz.md)）。
- 声明不能声明权限、不能授予权限、不能改变授权判定；界面只是入口。
- 所有动作仍经 CAP-02 调用网关，复用鉴权、超时、错误归一与审计。
- 高危能力（`risk_level: destructive`，如 `delete`/`restore`/`gc`）的确认语义由 [ADR-0021](0021-capability-execution-and-destructive-confirmation.md) 决定；声明式界面**不得**提供「跳过确认」或自动填充确认字段的能力。
- 敏感配置项只显示「已设置」，不回显明文；界面不得请求敏感值的明文。

#### 1.5 版本绑定

- 声明是清单的一部分，因此与**插件版本**和**包摘要**天然绑定；底座记录「类型 + 版本 + 包摘要 + 声明摘要」。
- 是否需要为声明式界面引入新的契约 MINOR 版本，以及最低契约版本要求：**待 OQ-011**，本草案不预写版本号。
- 同一插件升级后，声明随新包整体替换；不存在「旧声明配新能力」的混用状态。
- 声明缺省时视为「无自定义界面」，底座按能力 schema 生成最小默认视图；不得因此阻止插件安装或调用。

#### 1.6 升级与撤销

| 场景 | 处理 |
| --- | --- |
| 升级 | 新包校验通过后整体替换声明；实例配置按 ADR-0023 §5 保留；声明校验失败则拒绝升级 |
| 同版本重装 | 声明以包内清单为准重建，不保留旧缓存 |
| 撤销/卸载 | 入口与声明随实例撤销立即下线；不残留可访问的页面与缓存 |
| 降级/回滚 | 回到旧版本包时声明随之回滚；不保留新版本声明 |

一档不产生独立的静态资源文件，因此不存在「资源孤儿」问题；若将来引入二档，资源生命周期需重新设计（见 §2）。

#### 1.7 离线约束

- 声明中禁止外部 URL、外部 CDN、远程字体、远程图片、远程脚本与远程样式。
- 图标只能引用底座内置图标集的名称；未识别名称显示占位符，不发起网络请求。
- 底座渲染不依赖外网；部署在无外网环境时界面能力不降级。
- 任何需要访问外部网络的展示（如跳转插件自带站点）不在 v1 范围。

#### 1.8 审计与可观测

- 声明摘要作为插件静态事实的一部分记录；`installed` 事实包含「清单 + 声明」的校验结果。
- 通过界面发起的调用与直接调用走同一条审计路径，记录主体、实例、能力、结果；不额外记录页面点击流水。
- 声明校验失败、未知控件降级、未知展示类型降级必须写日志（插件类型、版本、失败位置），可被运维发现。
- 界面只展示底座接口已返回的数据，不引入第二套数据来源。

### 2. 二档：插件自带前端包（挂起，不进入 v1）

**结论：挂起为 idea（OQ-011 的单一挂起项），不进入 v1 范围，也不承诺未来必然实现。**

暂缓理由：

1. **风险等级不匹配**：底座管理界面持有生产机 SSH 凭据、插件证书私钥与会话；引入第三方 JavaScript 后，一旦沙箱、CSP 或同源隔离出现缺陷，攻击面直接落在最高权限的管理端。
2. **沙箱难以「证明安全」**：iframe `sandbox`、独立源、CSP、postMessage 白名单任一配置失误都可能造成越权；这类缺陷在评审中很难被穷尽验证。
3. **供应链与审核成本高**：插件可能来自多个团队或外部；要求对所有插件前端做代码审核与签名，成本高于收益，且审核结论会随插件升级失效。
4. **v1 需求可由一档覆盖**：配置表单与常见结果展示已能覆盖多数插件；为少数复杂界面引入整套前端沙箱模型不划算。
5. **与「界面资源随包留在底座侧」不冲突**：即使将来重启，远端插件也不需要在目标机托管前端资源；这一点只影响可行性，不构成现在做的理由。

若将来重启评审，必须一次性回答（当前**均未定**，合并为 OQ-011 的单条挂起项，不拆成独立 OQ）：

| 问题 | 说明 |
| --- | --- |
| 沙箱技术选型 | iframe `sandbox`（不含 `allow-same-origin`）+ 独立源的组合，或其它隔离方案；不得与宿主同源 |
| Host API 最小面 | 只开放调用、上下文读取与尺寸通知等最小集合；禁止读取凭据、直连数据库、访问文件系统、SSH、任意网络 |
| 第三方前端审核/签名 | 是否要求代码审核、签名与摘要锁定；升级是否重新审核 |
| 是否允许网络请求 | 默认禁止（`connect-src 'none'`）；若允许，域名白名单与代理方式待定 |

同时必须满足的前提（仅作为重启评审的门槛，不是已定设计）：严格 CSP、默认拒绝、与现有能力级授权对齐、资源随包且由底座托管、不从目标机加载、离线可用、升级与撤销可整体回收、加载与调用可审计。

## 暂缓与不纳入 v1 的方案

| 方案 | 说明 | 处理 |
| --- | --- | --- |
| 二档：插件自带前端包（沙箱 iframe + Host API） | 插件包内带静态资源，由底座托管并隔离运行 | **挂起为 idea**，不进入 v1；理由见 §2 |
| 微前端（运行时加载插件 JS 模块） | 共享宿主路由与状态 | 不纳入 v1：与二档同等风险，且隔离更弱 |
| 插件提供 Web Components 注入宿主文档 | 组件级复用 | 不纳入 v1：与宿主同 DOM，无法建立安全边界 |
| 插件服务端渲染 HTML 片段 | 插件返回 HTML 由宿主插入 | 不纳入 v1：等同允许插件注入标记与脚本 |

## 被否方案与原因

| 方案 | 否决原因 |
| --- | --- |
| 同源脚本注入（插件 JS 直接在管理端执行） | 插件脚本可获得会话、DOM 与同源接口，等于把管理端完全交给第三方代码 |
| 无沙箱 iframe | 仅加一层 iframe 不构成隔离；同源 iframe 可直接访问宿主 DOM |
| `sandbox="allow-scripts allow-same-origin"` | 二者同时开启可自行移除沙箱限制，隔离失效 |
| 从目标机加载界面资源 | 被入侵的目标机可替换界面并钓鱼；且目标机不承担前端托管职责 |
| 允许外部 CDN / 远程资源 | 破坏离线约束，引入不可控第三方与内容替换风险 |
| 给插件界面发放 API 令牌 | 令牌一旦泄露即可绕过界面直接调用，违背「授权始终在底座」 |
| 用声明式声明任意 URL 作为入口 | 可被用于钓鱼跳转与绕过底座导航 |
| 声明中支持脚本/表达式/自定义控件 | 等于换一种方式执行第三方代码，失去一档的安全属性 |

## 影响与约束

**正面**：不引入第三方前端代码即可覆盖多数插件的配置与结果展示；界面与能力 schema 同源，减少手写页面；无静态资源生命周期问题；离线可用；权限与审计路径不变。

**负面 / 代价**：复杂交互（多步向导、可视化编排、自定义图表）无法表达；控件与展示形态受底座枚举限制；声明本身需要 schema 校验与降级策略；插件作者需要学习声明约定。

**实现约束**：

- 一档只渲染数据，不执行任何插件提供的代码、模板或样式。
- 声明校验失败必须拒绝安装并给出可定位原因；未知类型只能降级为只读原始数据。
- 界面可见性与动作放行必须复用现有授权判定，不得新增旁路。
- 敏感配置值不得进入界面响应；界面不得请求明文。
- 禁止在声明中出现外部 URL、远程资源与内联脚本。

## 验证方式（若一档落地）

1. 清单声明表格展示 → 底座渲染表格，插件包内无任何前端文件。
2. 声明未知展示类型 → 降级为原始 JSON 并记录告警，页面不报错、不执行内容。
3. 未授权用户打开入口 → 不可见或明确拒绝；直接调用仍被网关拒绝。
4. 高危能力经界面触发 → 仍需确认字段，界面无法跳过。
5. 敏感配置项 → 只显示「已设置」，接口与页面均无明文。
6. 升级插件并修改声明 → 新声明整体生效；实例配置保留。
7. 撤销实例 → 入口与页面立即下线，无残留可访问地址。
8. 断外网环境打开页面 → 渲染正常，无外部请求。

## 待确认问题（均归 OQ-011）

**一档（v1 方向，proposed）**

- 声明可用的控件集合与各自约束。
- 结果展示形态清单（表格 / 键值 / 纯文本 / JSON 等）与字段顺序、列可见性。
- 是否允许自定义展示顺序与分组；允许到什么粒度。
- 入口与导航声明的范围（是否允许二级页面、是否只允许单页）。
- 声明式界面是否需要新的契约 MINOR 版本，以及最低契约版本要求。
- 声明校验失败与未知类型的降级策略是否如上文所述。

**二档（挂起，单条）**

- 沙箱技术选型、Host API 最小面、第三方前端审核/签名、是否允许网络请求——合并为一条挂起项，不进入 v1，不拆分为独立 OQ。
