# ADR-0022 远端插件证书体系与内置 CA 职责

- 状态：`accepted`
- 日期：2026-11-16
- 决策者：用户（远端常驻插件采用 TCP + 双向 TLS；证书由底座在下发安装时生成并配置到目标机）
- 实现：M6 已落地（内置 CA、ECDSA P-256、URI SAN 绑定插件+主机+用途、序列号吊销、mTLS 校验），基线见 [DOC-18](../18-m6-remote-plugins-and-instances.md)；轮换与备份待 OQ-047
- 关联：OQ-010（decided）、OQ-027（decided）、OQ-047、OQ-048、[ADR-0005](0005-daemon-rpc-transport.md)、[ADR-0006](0006-plugin-authz.md)、[ADR-0013](0013-plugin-credential-encryption.md)、[ADR-0014](0014-ssh-transport-and-host-credentials.md)、[ADR-0018](0018-daemon-process-custody-and-injection.md)、[DOC-09](../09-host-management-and-plugin-distribution.md)、[plugin-spec/03](../../plugin-spec/03-remote-protocol.md)

## 背景

远端常驻插件在目标机直接监听 TCP，底座跨主机调用。SSH 只用于下发安装，不承担调用传输（用户已否决 SSH 隧道与节点代理）。
因此调用链路必须在**没有底座进程**的目标机上独立完成身份认证，且不能依赖网络位置（回环、内网）作为安全边界。

需要一次定清楚：谁签发证书、证书绑定什么、何时签发、怎么轮换与吊销、私钥放哪、CA 私钥如何保护。

## 决策

**底座内置 CA 作为 v1 唯一签发者；下发安装时为每台主机上的每个插件签发服务端证书，底座自身持有客户端证书；两侧均校验对方证书；端口与证书解耦。**

### 1. 内置 CA 的职责边界

| 项 | 结论 |
| --- | --- |
| 角色 | 底座是唯一 CA（自签根证书），只为「底座 ↔ 远端插件」这一条链路签发证书 |
| 不承担 | 不作为通用 PKI：不签发用户证书、不签发其他系统证书、不提供 ACME/OCSP 服务、不向插件转发签发请求 |
| CA 私钥位置 | 只存在于底座数据目录，**永不下发**到任何目标机，也不进入插件包 |
| CA 私钥保护 | 使用 [ADR-0013](0013-plugin-credential-encryption.md) 的 AES-256-GCM 主密钥加密后落盘；文件 `0600`、所在目录 `0700`；主密钥轮换时必须重新加密（OQ-023） |
| CA 证书分发 | 作为下发产物之一写入目标机，供插件校验底座客户端证书 |
| 密钥算法与长度 | 待定（OQ-047），实现时随证书算法一并锁定，不得在规格中写死 |

### 2. 证书内容与标识绑定

| 证书 | Subject CN | Subject Alternative Name | Extended Key Usage | 绑定对象 |
| --- | --- | --- | --- | --- |
| 插件服务端证书 | `plugin:<plugin-id>` | URI `opsplatform://plugin/<plugin-id>/host/<host-id>` | `serverAuth` | 插件标识 + 主机标识 + 用途 |
| 底座客户端证书 | `base:<base-id>` | URI `opsplatform://base/<base-id>` | `clientAuth` | 底座节点标识 + 用途 |

规则：

- **插件标识**必须与清单 `identity.id` 逐字一致；**主机标识**必须是底座主机记录的唯一标识，不得使用地址或显示名。
- 校验方必须同时检查：链到内置 CA、EKU 匹配、CN/SAN 与期望值严格相等、证书有效期覆盖当前时间、序列号不在吊销名单。
- **端口不进入证书**：更换端口不触发重签；证书只回答「是谁」，不回答「在哪监听」。
- 证书链只下发叶子证书与 CA 证书；不下发中间 CA（v1 无中间 CA）。
- 证书序列号由 CA 生成且全局唯一；序列号是吊销与审计的主键。

### 3. 签发时机

| 场景 | 行为 |
| --- | --- |
| 下发安装（首次） | 生成密钥对与插件服务端证书，随插件包、CA 证书、按主机生成的配置文件、systemd unit 一并写入目标机 |
| 重复下发同一版本 | 若现有证书仍有效且未被吊销，**复用**，不重复签发；证书缺失或无效则重新签发 |
| 升级版本 | 复用现有证书（证书与插件版本无关）；仅当证书不可用时重签 |
| 证书到期前 | 由底座主动轮换（触发周期待 OQ-047），流程见 §4 |
| 撤销下发 | 停止服务并删除证书与私钥，同时把序列号加入吊销名单 |

底座客户端证书在底座首次启用远端调用时生成一次，供所有远端插件共用；其用途仅为「证明调用方是该底座节点」。

### 4. 有效期与轮换

- 证书有效期、轮换提前量、轮换周期：**待定（OQ-047）**，不得在规格或代码中写死。
- 轮换流程（顺序固定）：
  1. 底座签发新证书（新密钥对、新序列号），旧证书保持有效；
  2. 通过 SSH 下发新证书与私钥到目标机（原子替换，保留旧文件备份）；
  3. 重启插件服务（v1 **不承诺**证书热加载）；
  4. 底座以新证书完成握手与 `Ready` 探测；
  5. 成功 → 旧序列号加入吊销名单并删除旧文件；失败 → 回滚到旧证书并告警。
- 轮换失败不得导致「两侧证书都不被信任」；旧证书必须在新证书验证通过后才吊销。

### 5. 吊销与重签

| 项 | 结论 |
| --- | --- |
| 吊销载体 | 底座侧维护**序列号吊销名单**（持久化于底座数据目录/库），握手时拒绝已吊销序列号 |
| 插件侧是否维护 CRL | **不需要**。插件只校验「链 + EKU + 期望底座标识 + 有效期」，底座客户端证书由底座自行替换 |
| 重签 | 生成新密钥对与新序列号；旧序列号吊销；旧私钥在目标机删除 |
| 撤销下发 / 卸载 | 停止并禁用服务 → 删除 unit、证书、私钥、按主机配置 → 目标机插件包按卸载策略删除 → 吊销序列号 → 审计 |
| 私钥疑似泄漏 | 立即吊销序列号 → 重签 → 重启服务 → 审计；不得只删除文件而不吊销 |
| 主机记录删除 | 先执行撤销下发（含吊销），再删除记录；禁止留下仍可握手的证书 |

### 6. 私钥在目标机的存放与权限

| 文件 | 位置 | 权限 | 说明 |
| --- | --- | --- | --- |
| 服务端私钥 | 插件状态目录下 `tls/server.key` | `0600`，属主为服务账号 | 不在插件包内，不随版本切换覆盖 |
| 服务端证书 | 插件状态目录下 `tls/server.crt` | `0644` | 可读即可，无保密要求 |
| CA 证书 | 插件状态目录下 `tls/ca.crt` | `0644` | 用于校验底座客户端证书 |
| 按主机配置文件 | 插件状态目录下 `config.yaml` | `0600` | **只含路径与非敏感参数**，不含私钥或令牌 |

- 插件状态目录本身为 `0700`、属主为服务账号；其父目录不得全局可写。
- 私钥**不得**写入插件包、日志、审计、崩溃转储或备份归档；底座审计只记录序列号与指纹摘要。
- 具体的远端安装根目录与状态目录前缀属实现基线（OQ-041 / OQ-048），但上表的相对结构与权限属契约。

### 7. CA 私钥自身的保护与备份

- **保护**：加密落盘（主密钥），仅底座进程可读；不进入插件包、不进入下发产物、不出现在任何接口响应中。
- **备份**：备份必须同时包含 CA 证书与**加密后的** CA 私钥；明文私钥不得出现在备份介质中。备份频率、保留份数与异地策略待定（OQ-047）。
- **丢失后果**：CA 私钥丢失后无法签发或轮换，已签发证书在到期前仍可用，到期后所有远端调用失败。
- **恢复方式**：只能重建 CA 并重新下发全部远端插件证书（等价于重新安装），期间远端调用不可用；该过程必须审计。
- 主密钥轮换（OQ-023）与 CA 私钥重新加密必须同一批次完成，避免出现「主密钥已换、CA 私钥无法解密」。

## 被否方案与原因

| 方案 | 说明 | 否决原因 |
| --- | --- | --- |
| 远端 TCP 不使用 TLS | 实现最简单 | 调用面直接暴露在网络上，任何可达主机都能调用高危能力；与默认拒绝、审计要求冲突 |
| 仅服务端 TLS（单向） | 只让底座验插件 | 插件无法区分调用方，任何能连上端口的进程都可冒充底座 |
| 每台主机自签证书 + TOFU 锁存 | 免 CA | 轮换与吊销无统一入口；主机重置后无法区分「合法重签」与「中间人替换」 |
| 复用 SSH 主机密钥作为插件证书 | 少一套密钥 | SSH 主机密钥语义是「主机身份」，无法表达插件标识与用途；且与「SSH 只用于下发」的边界冲突 |
| 外部 PKI（Vault / step-ca / 企业 CA） | 标准化 | v1 单二进制、离线部署，引入外部依赖与运维负担；记 idea |
| 静态共享密钥 / PSK | 无需证书 | 无法轮换到实例级、无法表达主机绑定、泄漏后影响面大 |
| 私钥打进插件包 | 分发简单 | 包会被复制、缓存、归档；私钥随包扩散，无法按主机吊销 |
| CA 私钥随下发复制到目标机 | 目标机可自签 | CA 私钥落到不可信主机等于放弃整个信任体系 |
| 证书绑定端口 | 防止端口漂移 | 端口按主机覆盖是正常运维动作，绑定会导致无意义的重签与停机 |

## 影响与约束

**正面**：远端调用有明确的对端身份；证书与主机、插件绑定，可吊销可重签；私钥不下发到包内；端口调整不需要重签。

**负面 / 代价**：底座需实现 CA、证书签发/轮换/吊销与吊销名单；下发产物增加四类文件；目标机需要 systemd 与可写状态目录；
CA 私钥成为新的高价值资产，备份与主密钥轮换流程必须覆盖它。

**实现约束**：

- 底座不得在证书校验失败时降级为明文或跳过校验。
- 插件不得接受未通过 mTLS 的 TCP 连接，也不得提供明文监听开关。
- 证书与私钥的读取路径只能来自按主机生成的配置文件，不得来自环境变量或命令行值。
- 任何证书操作（签发、轮换、吊销、重签）必须产生审计事件，记录序列号与指纹，不记录私钥。

## 验证方式

1. 无客户端证书连接远端插件 → 握手失败，不进入 `Ready` 判定。
2. 使用其他插件的服务端证书 → 底座校验 CN/SAN 不匹配并拒绝。
3. 使用已吊销序列号的证书 → 握手被拒绝，错误可诊断。
4. 证书过期 → 握手失败，状态转 `unhealthy`，不重试到明文。
5. 端口按主机覆盖后 → 旧证书仍可通过校验，无需重签。
6. 轮换中途失败 → 回滚到旧证书后服务仍可调用，旧序列号未被吊销。
7. 撤销下发 → 服务停止、unit 与证书删除、序列号进入吊销名单、审计可查。
8. CA 私钥密文损坏 → 拒绝签发并显式失败，不生成不受信任的证书。
