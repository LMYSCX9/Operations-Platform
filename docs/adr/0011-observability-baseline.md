# ADR-0011 可观测性基线

- 状态：`proposed`
- 日期：2026-11-16
- 决策者：待定（用户）
- 关联：OQ-016、[DOC-06](../06-non-functional-requirements.md) §9、CAP-06

## 背景

运维平台自身必须可运维。需要确定：日志格式与字段、插件日志归属、指标是否暴露、追踪是否引入。
过度设计会让 v1 变重；缺失则排障困难。

## 决策（待确认）

1. 日志格式与必填字段。
2. 指标能力与格式。
3. 追踪是否纳入 v1。

## 推荐方案与理由

**结构化 JSON 日志（stdout）+ 插件日志归属字段 + 指标可选 + 追踪不承诺**

- 日志：JSON 行输出到 stdout/stderr，由容器或 systemd 采集；底座不内置日志轮转（如需文件输出，交给外部工具）。
- 必填字段（语义）：时间、级别、组件、消息、插件标识（若相关）、运行实例标识（若相关）、调用标识（若相关）、错误详情。
  字段名待定。
- 插件日志：命令式插件的 stderr 与常驻插件的日志，由宿主附加插件标识/实例标识后统一输出，**不得原样混入宿主日志而不带归属**。
- 指标：可选。若提供，暴露方式与格式待定（建议标准文本格式），指标清单待定。
- 追踪：v1 不承诺；调用标识可用于跨日志关联。

理由：日志是排障刚需且成本最低；指标与追踪在没有明确消费方（监控体系）时容易变成无用负担。

## 备选方案

| 方案 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. JSON 日志 + 可选指标（推荐） | 渐进 | 成本低、可采集 | 无分布式追踪 |
| B. 仅文本日志 | 最简 | 人工可读 | 机器解析差 |
| C. 完整可观测性栈 | 日志+指标+追踪 | 能力全 | v1 过重，依赖外部系统 |
| D. 内置日志文件轮转 | 自身管理 | 不依赖外部 | 与容器化理念冲突 |

## 影响

**正面**：排障路径明确；插件日志可归因；不引入额外运行时依赖。

**负面 / 代价**：需要统一字段约定并在 SDK/执行器中贯彻；指标能力缺位时容量分析需依赖外部手段。

**迁移成本**：低。指标与追踪可在不破坏日志契约的前提下增补。

## 约束

- 禁止记录凭据；敏感输入输出只记录摘要（NFR-LOG-05）。
- 日志级别变更需重启（与 ADR-0009 一致）。
- 插件日志必须能区分「插件自身错误」与「宿主调用失败」。
- 指标若提供，不得成为调用路径上的阻塞点（失败不影响业务）。

## 验证方式

1. 任意一次调用可在日志中通过调用标识串起完整链路（宿主 → 插件 → 返回）。
2. 插件输出日志无法污染结构化字段（例如通过换行注入伪造字段）。
3. 敏感字段不出现在日志中。
