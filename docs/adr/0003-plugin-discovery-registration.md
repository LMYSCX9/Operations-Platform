# ADR-0003 插件发现、注册与清单校验

- 状态：`accepted`
- 日期：2026-11-16（定稿）
- 决策者：用户（P0 六项批准，按推荐方案定稿）
- 关联：OQ-002、OQ-005（均已 decided）、[DOC-03](../03-plugin-model.md) §2~§4、[DOC-04](../04-plugin-lifecycle.md) §3、[plugin-spec/01](../../plugin-spec/01-manifest.md)

## 背景

底座需要知道「有哪些插件、在哪里、是否可用」。这决定了安装体验、离线部署能力，以及注册表的数据模型。
同时要确定清单（Manifest）的格式、字段集与校验方式——它是插件契约的入口。

## 决策

**目录扫描 + 清单校验 + 注册表持久化（嵌入式 SQLite）；清单为 YAML + 内置 JSON Schema 校验；安装后默认禁用；热加载为可选开关、默认关闭。**

### 1. 发现

- 启动时扫描配置指定的插件目录，**一个插件一个子目录**（子目录内为该插件包内容）。
- 发现阶段**不执行插件代码**，只读取静态信息。
- 热加载（目录监听）作为**可选开关**提供，**默认关闭**；开启后仍须走完整「校验 → 登记」流程。
- 不提供独立注册中心；不做插件市场。

### 2. 注册表

- 注册表是**唯一权威状态**；文件系统上有包不等于已登记、更不等于已启用。
- 持久化到嵌入式 SQLite（[ADR-0007](0007-persistence.md)），不存于插件目录内。
- 任何状态变化必须产生审计事件。

### 3. 清单

| 项 | 结论 |
| --- | --- |
| 格式 | YAML（与底座配置文件同格式） |
| 文件名 | `plugin.yaml`，位于插件包根目录 |
| 数量 | 一个插件包**恰好一个**清单、只描述**一个**插件 |
| 校验 | **内置 JSON Schema 校验**（解析 YAML → 按 schema 校验结构），再做语义校验（版本兼容、入口存在、路径不越界） |
| 字段集 | **最小必需字段**，见 [plugin-spec/01](../../plugin-spec/01-manifest.md) §2 |
| 编码 | UTF-8 |
| 敏感值 | 清单中**禁止**出现密钥、口令、令牌 |

### 4. 标识与命名

- 插件标识：**小写短横线**，形如 `[a-z][a-z0-9-]*`，全局唯一，不得含大写、下划线、中文、空格。
- 能力标识：`<插件标识>.<能力名>`，两段均为小写短横线或小写字母数字；能力名在同一插件内唯一。
  （原为「建议带插件标识前缀」，本次定稿改为**强制**，用于调用寻址与冲突判定。）
- 标识一经发布**不得复用**给不同语义。

### 5. 插件间依赖

- **v1 禁止**插件声明依赖其他插件或调用其他插件能力（与 INV-7 一致）。清单 schema 不接受依赖声明字段。

### 6. 安装与启用

- 校验通过 → 登记入注册表，状态为**已安装（installed）**。
- **安装后默认禁用**：必须由显式操作启用后才可被调用。下发安装（CAP-13）同样遵守此规则。

### 7. 冲突与多版本

- 同一标识同时存在多个版本时，注册表只保留**一个**已登记版本（候选为「最高且契约兼容」的版本）；
  其余包必须**显式报告冲突**，不得静默忽略。

## 被否方案与原因

| 方案 | 说明 | 否决原因 |
| --- | --- | --- |
| 文件监听作为唯一发现方式 | 只靠目录事件 | 状态一致性复杂，且离线/容器场景事件不可靠；降级为可选开关 |
| 显式安装 API 作为唯一入口 | 只能上传安装 | 离线部署不便，违背「安装即复制目录」的运维习惯；可叠加，不作基线 |
| 独立注册中心服务 | 集中管理多实例 | 与「单二进制、单节点」定位冲突（[ADR-0007](0007-persistence.md)） |
| 清单用 JSON / TOML | 替代 YAML | JSON 无注释、手写体验差；TOML 表达嵌套能力列表冗长；YAML 与底座配置文件统一，减少心智负担 |
| 自研清单校验器 | 手写规则 | 规则易漂移、错误定位质量差；内置 JSON Schema 校验器可直接产出字段级错误 |
| 字段集做「大而全」 | 预先堆砌可选字段 | 增加冻结面与误用风险；最小必需字段 + 未知字段忽略（[DOC-05](../05-extension-points-and-compatibility.md) §5）更利于演进 |
| 插件间依赖声明 | 允许 A 依赖 B | 引入依赖图、启动顺序与循环依赖问题，v1 不解决 |

## 影响与约束

**正面**：无外部组件；安装即复制目录；注册表可持久化并由审计追踪；schema 校验错误可定位到字段。

**负面 / 代价**：需维护清单 schema 及其版本；插件开发者必须先过 schema 校验才能看到语义错误；
标识格式收紧会使既有不合规标识无法登记（v1 尚无存量，成本可接受）。

**实现约束**：

- 清单 schema 属于**契约**，放在 SDK 契约目录内，与校验实现同源（[ADR-0012](0012-module-boundaries-and-sdk.md)）。
- 校验失败必须给出**字段路径 + 原因**，禁止只返回「校验失败」。
- 发现阶段不得因单个插件包损坏而中断其他插件的扫描。
- 未知字段按 [DOC-05](../05-extension-points-and-compatibility.md) §5 忽略，不得因未知字段拒绝登记（新增可选字段属 MINOR）。

## 验证方式

1. 缺 `identity.id` / 能力缺输入 schema / 契约版本不兼容的清单 → 被拒绝，错误含字段路径。
2. 标识含大写或下划线 → 被拒绝，错误指出违反的命名规则。
3. 清单中声明其他插件依赖字段 → 被拒绝（v1 不支持）。
4. 重复安装同一版本 → 幂等，注册表无重复记录。
5. 安装完成后直接调用 → 被拒绝（默认禁用），启用后才可用。
6. 删除插件包后重启 → 注册表与文件系统的差异可被识别并报告。
7. 同一标识两版本共存 → 冲突被显式报告，不作静默择一。
