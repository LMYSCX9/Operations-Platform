# ADR-0017 引入 golang.org/x/crypto（口令派生与 SSH 传输）

- 状态：`proposed`
- 日期：2026-11-16
- 决策者：待定（用户已批准引入方向，状态保持 `proposed`）
- 关联：OQ-037、OQ-040、OQ-041、[ADR-0006](0006-plugin-authz.md)、[ADR-0013](0013-plugin-credential-encryption.md)、[ADR-0014](0014-ssh-transport-and-host-credentials.md)、[DOC-13](../13-m2-identity-and-authz.md)、[DOC-14](../14-host-management-m3.md)

## 背景

M2 需要本地账号口令的不可逆派生值；M3 需要通过 SSH 建立连接、上传插件包并锁存主机指纹。
标准库没有口令派生函数，也没有 SSH 客户端实现：

- 自写 PBKDF2 属于密码学实现，难以证明常量时间与边界正确性；
- 自写 SSH 协议（密钥交换、认证、SFTP/scp）风险与工作量都不可接受；
- 调用系统 `ssh` 命令会引入外部依赖与输入转义风险，破坏单二进制交付。

## 决策

引入 `golang.org/x/crypto`（按需使用其中两个子包）：

| 子包 | 用途 | 里程碑 |
| --- | --- | --- |
| `golang.org/x/crypto/pbkdf2` | 账号口令派生，PBKDF2-HMAC-SHA256，210000 次迭代、16 字节盐、32 字节输出 | M2 |
| `golang.org/x/crypto/ssh` | SSH 客户端、认证、主机指纹校验、会话与文件传输 | M3 |

约束：

- 版本随 `go.mod` 锁定；不使用该模块中的实验性 API。
- 口令派生参数集中定义在 `internal/identity`，禁止散落；参数调整必须同步 DOC-13 与 OQ-040。
- SSH 主机指纹首次信任（TOFU）后锁存；指纹变更一律阻断，不提供忽略校验的开关。
- 私钥、口令只在建立连接时解密/使用，不写日志、不回显（ADR-0013、DOC-14）。

## 理由

- 两个子包都是 Go 官方维护（`x/` 仓库），纯 Go、无 cgo。
- `pbkdf2` 是 RFC 2898 的标准实现，避免自写密码学。
- `x/crypto/ssh` 支持公钥与口令认证、`known_hosts` 式回调，可满足 DOC-09 的指纹锁存要求。
- 与「单二进制、离线部署」一致：不依赖目标机或构建机上的 ssh 客户端。

## 备选方案

| 方案 | 说明 | 未采用原因 |
| --- | --- | --- |
| A. 自写 PBKDF2 | 不引入依赖 | 密码学实现不宜自写；难以证明常量时间与参数编码正确 |
| B. 仅用 `crypto/sha256` 加盐迭代 | 近似 KDF | 非标准构造，参数无法与业界对照，审计成本高 |
| C. 调用系统 `ssh` / `scp` | 复用目标机工具 | 依赖外部二进制；命令拼接与凭据传递有注入/泄漏风险；Windows 交付不一致 |
| D. 使用 `go-git` 式第三方 SSH 库 | 功能更全 | 依赖更重；`x/crypto/ssh` 已覆盖 M3 所需能力 |
| E. 不实现 SSH，仅本机插件 | 规避依赖 | 与已纳入 v1 的主机下发（CAP-13、DOC-09）冲突 |

## 影响

**正面**：口令与 SSH 均使用经过审计的实现；无 cgo、无外部二进制依赖。

**负面 / 代价**：新增依赖面；`x/crypto` 版本需随安全公告升级，升级时必须回归登录与下发链路。

**迁移成本**：低。M2/M3 之前代码不引用该依赖，不影响 M1 构建。

## 验证方式

1. `CGO_ENABLED=0 go build ./...` 通过，产物不依赖系统 OpenSSH。
2. 口令派生结果稳定、盐随机、相同口令不同盐得到不同派生值（单元测试）。
3. SSH 指纹首次保存、二次连接校验通过、指纹变化被阻断（单元测试或本地 sshd 手测，见 DOC-14）。
