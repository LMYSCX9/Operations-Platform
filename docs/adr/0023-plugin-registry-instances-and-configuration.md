# ADR-0023 插件注册、类型/实例模型与配置作用域

- 状态：`accepted`
- 日期：2026-11-16
- 决策者：用户（插件「被注册」而非自报；类型与实例分离；配置按实例）
- 实现：M6 已落地（schema v7、类型/能力/实例/配置/探测/证书绑定/注册事件），基线见 [DOC-18](../18-m6-remote-plugins-and-instances.md)
- 关联：OQ-002（decided）、OQ-010/OQ-027（decided）、OQ-037、OQ-049、OQ-050、OQ-051、[ADR-0003](0003-plugin-discovery-registration.md)、[ADR-0006](0006-plugin-authz.md)、[ADR-0007](0007-persistence.md)、[ADR-0013](0013-plugin-credential-encryption.md)、[ADR-0018](0018-daemon-process-custody-and-injection.md)、[ADR-0022](0022-remote-plugin-pki-and-mtls-certificates.md)、[DOC-03](../03-plugin-model.md)、[DOC-04](../04-plugin-lifecycle.md)、[DOC-08](../08-storage-and-data-directory.md)、[DOC-09](../09-host-management-and-plugin-distribution.md)、[DOC-17](../17-plugin-registry-and-configuration.md)

## 背景

插件被安装到多台业务机后，底座必须回答：

- 这台主机上装了什么插件、版本是什么、能做什么；
- 这些信息由谁提供、是否可信；
- 同一插件装在多台主机上时，如何查询、授权、配置与调用；
- 包被删除、进程被杀、清单与实机不一致时，界面显示什么；
- 配置项如何声明、按什么粒度填值、密文如何落库与注入。

如果让插件「自报」，被入侵的主机可以伪造能力、隐藏高危标记、谎报版本与健康状态。因此事实来源必须落在底座的安装事实与可验证探测上。

## 决策

**插件被底座注册，不自报为事实来源；插件类型与实例分离；状态分三层并带过期与漂移处理；配置作用域落到实例；调用、任务、批量操作与授权都以实例为目标。**

### 1. 注册方向：被注册，而非自报

| 项 | 结论 |
| --- | --- |
| 注册发起者 | **底座**。在安装/下发事务中创建或更新实例记录 |
| 事实来源 | ① 下发/安装记录（哪台主机、哪个包、何时、何种托管方式）；② 包内清单（经 JSON Schema 校验，记录包摘要）；③ 证书绑定关系（插件标识 + 主机标识 + 序列号）；④ 底座探测结果 |
| 自报的定位 | 仅作**参考与漂移检测**，不得作为唯一事实来源，不得用于自证健康或扩权 |
| 禁止 | 不得由插件调用接口「注册自己」；不得以插件心跳中的能力列表覆盖底座记录；不得因自报健康而把实例标为可调用 |
| 防伪造理由 | 主机被入侵后，攻击者可以伪造能力声明、隐藏 `destructive`、谎报版本、长期伪报健康；证书只证明「对端是哪个实例」，不证明「它宣称的能力为真」。只有底座掌握的包摘要、清单与安装记录不可由被控主机单方面改写 |

补充规则：

- 远端插件的「已安装」事实来自底座的下发事务记录 + 目标机文件存在性校验，不来自插件进程。
- 本机插件的「已安装」事实来自底座插件目录扫描 + 包摘要，不来自插件输出。
- 同一 `(主机, 插件类型)` 只允许一个活动实例；重复安装视为升级或幂等重装，不产生第二个实例。

### 2. 插件类型与实例

| 概念 | 定义 | 标识 | 归属 |
| --- | --- | --- | --- |
| 插件类型（type） | 一个插件包所代表的能力集合与清单事实 | `plugin_id` + 版本 | 全局（跨主机共享的能力与配置声明） |
| 插件实例（instance） | 某一台主机上的一次具体安装 | `instance_id`（由底座生成，含主机与插件信息） | 单台主机 |

规则：

- 同一类型安装在 N 台主机上产生 N 个实例；能力定义属于类型，运行状态属于实例。
- 查询与界面：类型用于「有哪些能力、怎么用」；实例用于「在哪台机器上可用、当前是否可调用」。
- 调用、定时任务、批量操作的目标一律是**实例**，不得只给类型。
- 卸载/撤销只影响实例，不删除类型（类型随最后一个实例消失或保留为目录项，保留策略见 §4）。
- 本地插件同样有实例：`instance_id` 对应本机安装，不允许「无实例的插件」。

#### 2.1 与 ADR-0003（目录扫描发现）的关系

ADR-0003 的「目录扫描 + 清单校验」继续有效，但语义收窄为**发现类型**：

- 扫描对象是插件包，产出「类型候选」；安装/启用时才创建**实例**。
- 远端主机不参与目录扫描；远端实例只来自下发记录。
- 注册表从「插件表」演进为「类型 + 实例」两张逻辑实体；既有本地记录迁移为一个本机实例。
- 扫描发现的新包不得自动获得实例，更不得自动可调用；必须显式安装/启用。

### 3. 状态分层

| 层 | 内容 | 来源 | 更新时机 | 过期与漂移 |
| --- | --- | --- | --- | --- |
| 静态事实 | 类型标识与版本、包摘要、能力清单（名称、输入/输出 schema、`risk_level`、`concurrency`）、权限声明、配置项声明、托管方式、默认端口 | 包内清单 + 安装事务 + 证书绑定 | 安装/升级/撤销；扫描只更新类型候选 | 与实机不一致 → `drifted`，停止调用并要求重装/复核；不得用自报覆盖 |
| 运行状态 | `installed` / `started` / `callable` / `unhealthy` / `disabled` / `revoked` | 底座探测（进程/端口/TLS/`Ready`/`Health`）+ 调用失败降级 + 下发事务 | 每次探测、每次调用结果、每次启停 | 超过探测 TTL 未刷新 → `unknown`，**不得**继续显示为可调用；连续调用失败达阈值 → 降级 `unhealthy` |
| 自报信息 | `GetVersion` 的实际契约/插件版本、可选的能力自述、健康自述 | 插件进程 | 探测时读取 | 只用于比对与漂移告警；不作为能力事实来源，不作为健康唯一依据 |

漂移处理：

| 场景 | 判定 | 动作 |
| --- | --- | --- |
| 远端进程被杀 / systemd `failed` | 探测失败 | `started=false`、`callable=false`；保留静态事实；告警 |
| 包被删除 / 摘要不符 | 文件校验失败 | `installed=false`、`callable=false`；标记 `drifted`；禁止调用，提示重新下发 |
| 实机版本与注册版本不一致 | `GetVersion` 与静态事实不符 | `drifted`；隔离（拒绝调用）；要求升级/重装对齐 |
| 自报能力多于清单 | 集合不一致 | 不采纳自报；记漂移审计；继续以清单为准 |
| 证书序列号与绑定不符 | TLS 校验失败 | 不可调用；标记证书异常；要求重签 |
| 主机长期不可达 | 探测超时 | `unknown` + `unreachable`；不影响历史执行记录 |

### 4. 逻辑存储模型（不写字段名与 SQL）

| 实体 | 说明 | 关键关系 |
| --- | --- | --- |
| 主机 | 已纳管主机 | 1:N 实例 |
| 插件类型 | 插件包事实：标识、版本、清单摘要、能力集合、配置声明、托管能力、默认端口 | 1:N 能力；1:N 实例 |
| 能力 | 按类型独立存储的能力定义（名称、输入/输出 schema 引用、`risk_level`、取消支持） | N:1 类型 |
| 插件实例 | 某主机上的一次安装：类型引用、版本、托管方式、生效端口、证书序列号/指纹、启用状态、安装来源 | N:1 主机；N:1 类型 |
| 实例配置 | 按实例保存的配置值；敏感项加密存储 | N:1 实例 |
| 探测记录 | 每次探测的时间、结果、耗时、失败原因 | N:1 实例 |
| 执行记录 | 调用/定时任务的历史（已存在的实体，增加实例引用） | N:1 实例 |
| 证书绑定 | 序列号、指纹、绑定的类型/主机/用途、签发/到期/吊销状态 | N:1 实例 |
| 注册审计 | 安装、升级、撤销、漂移、配置变更、权限变更 | 关联实例 |

设计要点：

- **能力清单独立一份**，以类型为键；「按能力查实例」= 能力 → 类型 → 该类型的活动实例。避免在每个实例上复制能力定义造成不一致。
- 实例只引用类型版本；升级时更新引用并保留历史版本记录（回滚需要）。
- 探测记录与执行记录按时间保留，保留期与上限待 OQ-049。
- 具体字段名、索引与 SQL 属实现基线，不在本 ADR 固定。

### 5. 配置作用域：实例

- 清单声明**可配置项**：键、类型、是否必填、是否有默认值、是否敏感、说明；声明属契约（见 plugin-spec/01、plugin-spec/11）。
- **填值发生在实例维度**：下发到某台主机时由用户填值，底座按声明校验（类型、必填、枚举范围）后落库；同一类型在不同主机可有不同值。
- 敏感值：密文落库（复用 [ADR-0013](0013-plugin-credential-encryption.md) 的 AES-256-GCM 与主密钥），接口只返回掩码，不可导出明文。
- 注入方式：
  - 本机：底座生成配置文件（`0600`）并经 `--ops-config` 传入；敏感值在文件中以明文出现，但文件权限受限、不写日志。
  - 远端：随下发产物写入按主机生成的配置文件（`0600`），原子替换；证书材料单独存放（ADR-0022 §6），不写进配置值。
- 与证书的关系：证书/私钥是**底座签发的身份材料**，不是用户配置项；不得由配置项覆盖或替换。
- 升级/重装：
  - 同一实例升级版本：按 `instance_id` 保留既有配置值；新版本新增必填项 → 安装前阻止并要求补填；删除的键保留但标记为不生效（回滚可用）。
  - 同版本重装：保留配置；差异只重建运行产物。
  - 类型变更（配置项类型/枚举变化）→ 校验失败并显式报错，不静默转换（迁移策略待 OQ-051）。
  - 撤销下发/卸载：删除实例及其配置（含密文）；是否保留一段可恢复期待 OQ-051。

### 6. 使用路径与授权粒度

| 场景 | 目标 | 说明 |
| --- | --- | --- |
| 单次调用 | 实例 | 必须给出 `instance_id`；仅给类型时拒绝（批量需显式展开） |
| 定时任务 | 实例 | 任务绑定实例；实例被撤销时任务转失败并告警，不静默改投其他主机 |
| 批量操作 | 实例集合 | 由用户选择实例或按类型展开；展开结果在执行前固化并审计 |
| 能力展示 | 类型 | 按类型聚合展示能力与说明；同时给出提供该能力的实例数 |
| 权限判定 | **实例** | 最终判定落到实例；类型级授权仅作为「批量授予模板/默认值」，展开为实例集合后逐实例判定 |

授权补充：

- 默认拒绝不变（ADR-0006）；证书与实例存在都不代表已授权。
- 实例级授权记录必须能回答「谁在哪些主机上能调用哪些能力」。
- 类型级模板与实例级例外的优先级、以及是否允许跨主机批量授权：待 OQ-050。

接口族（路径为语义约定；具体字段与响应结构属实现基线）：

| 路径 | 方法 | 语义 |
| --- | --- | --- |
| `/api/plugin-types` | GET | 类型目录（能力、配置声明、版本） |
| `/api/plugin-types/{typeId}` | GET | 类型详情与实例计数 |
| `/api/plugin-instances` | GET | 实例列表（可按主机、类型、状态过滤） |
| `/api/plugin-instances/{instanceId}` | GET | 实例详情（静态事实 + 运行状态 + 漂移） |
| `/api/plugin-instances/{instanceId}/probe` | POST | 触发一次探测 |
| `/api/plugin-instances/{instanceId}/probes` | GET | 探测历史 |
| `/api/plugin-instances/{instanceId}/config` | GET / PUT | 读取（敏感项掩码）/ 更新配置并校验 |
| `/api/plugin-instances/{instanceId}/capabilities/{capability}/invoke` | POST | 对实例调用能力 |
| `/api/capabilities` | GET | 能力目录（按类型聚合） |
| `/api/capabilities/{capability}/instances` | GET | 按能力反查可调用实例 |
| `/api/hosts/{hostId}/distributions` | POST / GET | 下发安装（创建/更新实例） |
| `/api/distributions/{id}` | GET / DELETE | 下发详情 / 撤销（停服务、清产物、吊销证书、删实例配置） |

兼容说明：既有 `/api/plugins` 与 `/api/plugins/{id}/capabilities/{cap}/invoke` 保留为「本机类型目录 + 本机实例」的别名；
新代码与文档以实例路径为准。别名不得引入第二套状态语义。

### 7. 界面展示

- **实例列表**：主机、类型、版本、托管方式、`installed/started/callable`、漂移标记、最后探测时间与结果。
- **按能力反查**：某能力由哪些实例提供、各自状态；不可调用实例必须显式标注原因。
- **状态与漂移提示**：区分「未安装」「未启动」「不可调用（握手/就绪失败）」「不健康」「配置漂移」「证书异常」「主机不可达」；禁止只显示一个笼统的「异常」。
- **配置编辑入口**：按实例编辑；展示声明（类型、必填、说明），敏感项只显示是否已设置，不回显明文。
- **探测历史**：时间、结果、耗时、失败阶段；可手动触发探测。
- **下发入口**：从主机详情发起；展示「已安装 / 已启动 / 可调用」三段进度与失败阶段。

## 被否方案与原因

| 方案 | 说明 | 否决原因 |
| --- | --- | --- |
| 插件自报注册（主动上报能力与状态） | 实现自然 | 主机被入侵后可伪造能力、隐藏高危、谎报健康；无法作为审计事实来源 |
| 插件心跳覆盖注册表 | 实时性好 | 心跳可伪造、可重放；离线主机状态会凭空消失 |
| 只建「插件」一张表 | 模型简单 | 多主机安装无法表达，调用与配置无处落；权限只能做到类型级 |
| 能力复制到每个实例 | 查询简单 | 版本升级与漂移时必然不一致，且体积随主机数膨胀 |
| 配置挂到类型 | 复用方便 | 不同主机需要不同端口/路径/账号，类型级配置无法满足 |
| 配置放插件数据目录由插件自管 | 插件自治 | 底座无法校验、无法审计、无法在升级时保留或回滚 |
| 敏感配置明文落库 | 简单 | 违反 ADR-0013 与 NFR-SEC-08 |
| 探测失败即删除实例 | 状态干净 | 丢失审计与恢复依据；主机短暂不可达不应等于卸载 |
| 以自报健康替代主动探测 | 省一次连接 | 自报不可信；且无法覆盖进程被杀、证书过期、端口不通 |
| 授权只到类型 | 管理简单 | 无法表达「同一插件只在某几台主机允许调用」，违反最小权限 |

## 影响与约束

**正面**：注册事实可审计、可追溯；多主机安装有明确模型；能力查询与实例状态解耦；配置按实例落地，升级可保留；
授权可精确到主机；界面能区分失败阶段。

**负面 / 代价**：数据模型从单表变为多实体；扫描/安装/探测/升级都要维护类型与实例的一致性；
配置需要版本化校验与迁移策略；实例级授权增加管理成本。

**实现约束**：

- 任何注册写入必须来自底座事务，且带操作者与时间；插件无注册写权限。
- 实例状态不得只由单一来源推导；`callable` 必须同时满足「静态事实一致 + 探测成功」。
- 探测结果必须带时间戳；读取方必须检查是否过期，过期一律按 `unknown` 处理。
- 自报与静态事实不一致时，优先保护底座事实，并进入隔离流程。
- 配置校验失败不得部分写入；敏感值不得进入日志、审计、错误详情。

## 验证方式

1. 远端插件进程被杀 → 下次探测后 `callable=false`，静态事实保留，界面显示「未启动」而非「未安装」。
2. 删除目标机包文件 → 探测判定 `installed=false` 且 `drifted`，调用被拒绝。
3. 插件自报能力多于清单 → 不新增能力，记录漂移审计。
4. 同一类型安装在 3 台主机 → 产生 3 个实例；按能力反查返回 3 个实例及各自状态。
5. 给某实例改配置 → 仅该实例生效；其他实例不受影响。
6. 升级版本且新增必填配置 → 未补填前拒绝升级，已有值保留。
7. 撤销下发 → 实例删除、配置删除、证书吊销、任务因目标缺失而失败并告警。
8. 探测结果过期 → 界面与接口显示 `unknown`，不得继续显示可调用。
9. 仅给类型发起调用 → 拒绝并提示选择实例。
10. 实例级授权拒绝 → 返回无权限，不因「类型已授权」而放行。
